КРАТКОЕ РЕЗЮМЕ
--------------
Вылет в подсистеме сериализации игровых данных HD-мода. Огромная
функция sub_112CAA0 (56 КБ, строки диагностики «_File_::operator»)
обрабатывает контейнер записей переменной длины. Итератор sub_10A2550
обходит записи, вычисляя смещение следующей по полю размера каждой
записи, без проверки границ контейнера. Одна из записей оказалась
повреждена: вычисленное смещение увело обход на ~389 МБ за начало
контейнера (0x0893C064), в незанятую память (0x1FD3F396). Попытка
прочитать поле типа записи по этому адресу вызвала сбой.

Контейнер заполняется из сетевого сообщения (сетевая партия,
диспетчер сообщений sub_11791A0 проверяет версию-таймстемп
0x4CC398). Что именно повредило данные — передача, гонка потоков
или перехлёст кучи — по одному сокращённому минидампу установить
нельзя. Нужен полный дамп памяти (Sys.FullDump = 1).

6. Механизм сбоя
----------------
Итератор sub_10A2550 обходит массив записей переменной длины:

.text:010A2557                 lea     eax, [ecx+4]
.text:010A2560                 movsx   ecx, word ptr [eax]
.text:010A2563                 mov     edx, [ecx+eax+47h]
.text:010A2567                 add     eax, 4Ch
.text:010A256A                 add     edx, 7
.text:010A256D                 shr     edx, 3
.text:010A2570                 add     edx, ecx
.text:010A2572                 add     eax, edx
.text:010A2574                 sub     esi, 1
.text:010A2577                 jnz     short loc_10A2560

Каждая запись: поле типа (16 бит, знак) в начале, поле длины
по смещению (тип + 0x47), фиксированный заголовок 0x4C байт,
переменная часть ((длина + 7) >> 3) + тип байт. Итератор
складывает размеры и переходит к следующей записи.

Проверок границ НЕТ: итератор не знает общего размера контейнера
и не проверяет, что вычисленный адрес следующей записи остаётся
в пределах выделенной памяти. При порче поля типа или длины
хотя бы одной записи обход уходит за пределы контейнера.

В данном краше: контейнер по ESI = 0x0893C064, результат обхода
EDI = 0x1FD3F396. Разница 0x1FD3F396 − 0x0893C068 ≈ 0x17403330
(~389 МБ) — обход ушёл далеко за пределы контейнера в незанятую
память. Адрес 0x1FD3F396 не принадлежит ни одному модулю
(диапазоны: h3hota.exe 0x400000–0x6E7000, HD_HOTA.dll
0x3990000–0x4B87000, hota.dll 0x6E420000–0x72AB2000).

7. Первопричина
---------------
Данные контейнера повреждены во время работы. Контейнер заполняется
из сетевого сообщения: диспетчер sub_11791A0 принимает объект
сообщения, проверяет версию-таймстемп (0x4CC398 ≈ 26.10.2010)
и передаёт в обработчик sub_111DAB0 -> sub_112CAA0.

Возможные источники порчи:
- повреждение данных при сетевой передаче;
- гонка потоков (другой поток изменяет контейнер одновременно
  с чтением);
- перехлёст кучи (соседнее выделение записало в контейнер);
- использование после освобождения (контейнер освобождён,
  память перераспределена).

По одному сокращённому минидампу (без кучи) различить эти
варианты невозможно. Содержимое контейнера в момент сбоя
недоступно — минидамп содержит только код и стек.

Виновный код (итератор без проверки границ и потребитель,
доверяющий результату) находится в HD_HOTA.dll - закрытом
модуле HD-мода (репорт разработчикам, не правка кода).

11. Воспроизведение вылета
--------------------------
Условие активации пути: сетевая партия (Game Type = 2,
Network Game = 1), обработка сообщения с версией-таймстемпом
0x4CC398, версия формата < 11.

Базовый сценарий:
- Запустить сетевую партию HotA (HotA 1.8.0, HD 5.7 R33).
- Играть до дня ~15 (день сбоя в логе).
- Наблюдать за вылетом при обработке сетевых сообщений.

Вылет недетерминированный: зависит от момента порчи данных
контейнера. Вероятностный путь: повторять сетевые партии
на разных картах, фиксировать вылеты с адресом +0x134AD0
и сопоставлять содержимое контейнера (нужен полный дамп).

Дифф-тест: включить Sys.FullDump = 1 в hota.ini для снятия
полного минидампа с кучей. В отладчике проверить содержимое
контейнера по ESI и поля записей (тип, длина) в момент сбоя —
это покажет, какая запись повреждена и чем.

Достоверность и ограничения
----------------------------
Подтверждено:
- Адрес сбоя сопоставлен с листингом R33 (entry point, timestamp).
- Механизм доказан арифметикой: EDI = 0x1FD3F396 = адрес сбоя,
  инструкция movsx eax, word ptr [edi] читает по этому адресу.
- Итератор sub_10A2550 прочитан: обход записей переменной длины
  без проверки границ, результат 0x1FD3F396 при контейнере
  0x0893C064 — уход на ~389 МБ за начало.
- Цепочка вызовов восстановлена по V2 и V1: диспетчер сообщений
  sub_11791A0 -> sub_111DAB0 -> sub_112CAA0.

Ограничения:
- Минидамп сокращённый (106 КБ, без кучи): содержимое контейнера
  и повреждённой записи недоступно.
- Источник порчи не установлен: сетевая передача, гонка потоков,
  перехлёст кучи или использование после освобождения — по статике
  не различить.
- Единичный дамп: частота и воспроизводимость неизвестны.
- Родственные вылеты в той же функции из других версий HD
  имеют разные механизмы (NULL, NULL+6, дикий указатель);
  объединение в один дефект не доказано.

ВЫВОД
-----
Вылет в подсистеме сериализации игровых данных HD-мода
(HD_HOTA.dll). Итератор записей переменной длины sub_10A2550
вернул дикий указатель 0x1FD3F396 из-за порчи данных контейнера
в сетевой партии. Чтение поля записи по этому адресу вызвало
нарушение доступа. Итератор не проверяет границ контейнера,
но корень проблемы — не отсутствие проверки, а сама порча данных.
Что именно повредило контейнер, по сокращённому минидампу
установить нельзя. Для диагностики нужен полный дамп памяти
(Sys.FullDump = 1) и повторный вылет. Виновник — HD-мод
(закрытый модуль); материал для репорта разработчикам.
