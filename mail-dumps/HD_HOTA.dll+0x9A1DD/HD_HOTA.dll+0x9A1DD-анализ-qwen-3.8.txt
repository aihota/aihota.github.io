АНАЛИЗ ВЫЛЕТА HD_HOTA.dll+0x9A1DD
====================================

Модель: Qwen 3.8
Дата: 01.08.2026
Заключение: HD-мод: пропущена проверка NULL после получения клетки карты в функции «починки» карты приключений

Визуализация вылета
-------------------

(врезка extra.html)

КРАТКОЕ РЕЗЮМЕ
--------------

Вылет происходит в функции «починки» карты приключений HD-мода (sub_1099940,
строка "HD.Af.RepareFunc"). Функция вызывает A0_GameMap_GetCell для получения
клетки карты и сразу обращается к полю [+1Eh] возвращённого указателя, не
проверяя его на NULL. Когда база клеток карты ещё не загружена (поле [+0xD0]
объекта GameMap равно нулю), GetCell возвращает нулевой указатель, и чтение
[0+1E] вызывает нарушение доступа по адресу 0x0000001E.

Примечательно, что четыре других вызова GetCell в этой же функции проверяют
возврат на NULL (test reg, reg; jz), а пятый — нет. Дефект стабильно
воспроизводится в четырёх логах трёх сборок (R23, R28, R35), всегда в первый
игровой день (Day 1 1 1), при первой перерисовке диалога.

    .text:004086EB  imul    eax, edx

    .text:004086FE  retn    0Ch

GetCell — чисто арифметическая функция: результат = cells_base + индекс * 38.
Она НЕ возвращает NULL явно; нулевой результат возможен только при
cells_base = 0 и индексе = 0.

После возврата GetCell регистры: EAX = результат (в EBX), ECX = cells_base
(из [this+0xD0]), EDX = x. В дампе EBX = ECX = EDX = 0, что подтверждает:
cells_base = 0, координаты (0, 0, 0), результат = 0.

5. Первопричина
---------------

Модуль виновника: HD_HOTA.dll (sub_1099940, «HD.Af.RepareFunc»)
Замещаемая функция SoD: A0_Dlg_Redraw_sub_5FF5E0 (0x5FF5E0)
Поставщик данных: A0_GameMap_GetCell_sub_4086D0 (h3hota.exe, 0x4086D0)
Глобал: A0_AdvMgr_dword_6992B8 (h3hota.exe, 0x6992B8)

Указатель this для GetCell берётся из цепочки:

    .text:0109A1CA  mov     eax, 6992B8h         ; A0_AdvMgr_dword_6992B8
    .text:0109A1CF  mov     ecx, [eax]           ; объект AdvMgr
    .text:0109A1D6  mov     ecx, [ecx+5Ch]       ; GameMap из [AdvMgr+5Ch]

Поле GameMap+0xD0 (база клеток карты) равно нулю: карта ещё не загружена
или находится в переходном состоянии. GetCell вычисляет
cells_base + индекс * 38 = 0 + 0 * 38 = 0 и возвращает нулевой указатель.

Дефект НЕ унаследован от SoD: оригинальная A0_Dlg_Redraw_sub_5FF5E0
работает только с элементами диалога (перебирает список this->first_item
и вызывает виртуальные методы отрисовки) и НЕ обращается к клеткам карты.
Вызов GetCell — исключительно код HD-мода.

6. Условия сбоя
---------------

- Первый игровой день (Day = 1 1 1 во всех 4 логах) — партия только
  начата
- Одиночная игра (Network Game = 0)
- Первая перерисовка диалога: хук sub_109A660 срабатывает, когда
  "HD.Af.Fixed" ещё = 0
- База клеток карты (GameMap+0xD0) в этот момент равна нулю — данные
  карты не готовы
- Graphics.Mode: 5 (x3 лога) и 7 (x1 лог) — не влияет (краш в логике,
  не в отрисовке)
- Разные карты и разные игроки — не зависит от конкретной карты

7. Воспроизведение вылета
--------------------------

Условие активации пути: первая перерисовка диалога в партии (хук
sub_109A660 на A0_Dlg_Redraw), когда "HD.Af.Fixed" = 0 и база клеток
карты ещё не инициализирована.

Базовый сценарий:

- Начать одиночную партию на любой карте
- Дождаться первого диалога (перерисовка интерфейса) в первый
  игровой день
- Если база клеток карты в момент перерисовки равна нулю —
  происходит краш

Краш ненадёжен: зависит от момента, когда перерисовка диалога
совпадает с ещё не загруженными данными карты. Частота низкая
(4 лога на несколько месяцев), что указывает на узкое окно
состояния.

8. Достоверность и ограничения
-------------------------------

Подтверждено:

- Адресная арифметика: EBX(0) + 0x1E = 0x0000001E = faulting address
- Инструкция краша попадает на границу инструкции в листинге R35
- Побайтное совпадение кода в R23, R28 и R35 (функция идентична)
- Четыре из пяти вызовов GetCell проверяют NULL — пропущенная проверка
- SoD-оригинал (A0_Dlg_Redraw) не обращается к клеткам карты
- Все 4 лога: Day 1 1 1, все регистры 0, один адрес сбоя

Ограничения:

- Точный момент, когда cells_base = 0 (не загружена vs освобождена),
  по статике не установить — нужен минидамп с кучей или рантайм-
  наблюдение
- Минидамп (.dmp) сокращённый (96 КБ, без кучи) — содержимое объекта
  GameMap не проверить

ВЫВОД
-----

Виновник — HD-мод (HD_HOTA.dll). В функции «починки» карты приключений
sub_1099940 (модуль "HD.Af", строка "HD.Af.RepareFunc") пропущена
проверка на NULL после вызова A0_GameMap_GetCell. Четыре соседних
вызова в той же функции проверяют возврат; один — нет. Когда база
клеток карты равна нулю (данные карты не готовы), GetCell возвращает
нулевой указатель, и обращение к полю [+1Eh] вызывает краш.

Дефект проявляется в первый игровой день при первой перерисовке
диалога, не зависит от карты, игрока или графического режима.
Подтверждён 4 логами в 3 сборках (R23, R28, R35).
