АНАЛИЗ ВЫЛЕТА  HD_HOTA.dll+0x19F670  (окно выбора карты и список файлов)
================================================================================

    Модель: GPT-5.6 Sol
    Дата:   15.08.2026
    Заключение: HD_HOTA.dll выводит строки каталога при недопустимом
    начальном индексе и не проверяет сумму начального индекса и номера строки.


КРАТКОЕ РЕЗЮМЕ
--------------

    Вылет происходит в коде HD-мода, который получает имя записи каталога
    для окна выбора карты. Функция sub_119F670 начинает с чтения первого
    dword записи по адресу ECX. В момент исключения ECX равен 0x041922A4,
    и этот же адрес указан как адрес неудавшегося чтения.

    DMP сохранил не только регистры, но и поля объекта и локальные значения
    вызывающей функции. Массив содержит 184 записи размером 0xCA4: начало
    0x04100020, конец 0x04191600, допустимые индексы 0..183. Начальный индекс
    прокрутки уже равен 184. Цикл ограничивает только номер видимой строки,
    но строит фактический индекс как начальный индекс плюс номер строки.
    Поэтому он сначала обращается к индексу 184, а затем при ESI=1 - к
    индексу 185. Адрес второй недопустимой записи 0x041922A4 и вызвал AV.

    Это локально доказанный выход за границы. Не установлено только то,
    какое предшествующее действие оставило начальный индекс равным числу
    записей. Наиболее сильный дополнительный случай найден в HD 5.7 RC11:
    он падает в той же межверсионной функции и из той же функции вывода,
    но без DMP нельзя доказать, что его причина также равна выходу за конец.

2. Проверка листинга и адреса
-----------------------------

    Для HD 5.7 R40 выбран modules/HD_HOTA.dll-5.7 R40.txt с imagebase
    0x01000000. Модуль загружен по 0x04620000. Пересчёт сходится:

    0x047BF670 - 0x04620000 = 0x0019F670
    0x01000000 + 0x0019F670 = 0x0119F670

    Адрес 0x0119F670 является началом sub_119F670 и границей инструкции.
    Сохранённые в DMP байты 83 39 00 56 57 8D B1 C9 05 00 00 совпадают
    с листингом.

    .text:0119F670 sub_119F670     proc near
    .text:0119F670                 cmp     dword ptr [ecx], 0
    .text:0119F673                 push    esi
    .text:0119F674                 push    edi
    .text:0119F675                 lea     esi, [ecx+5C9h]

    Семья адресов между сборками проверялась по телу функции, строке
    <HD3FMDir> и размеру записи 0xCA4, а не по одному RVA. Эквивалентная
    функция найдена во всех 30 доступных листингах HD_HOTA.dll.


3. Точка сбоя
-------------

    Инструкция cmp dword ptr [ecx], 0 читает четыре байта по ECX.
    Машинная проверка эффективного адреса дала:

    ECX = 0x041922A4
    [ECX] = 0x041922A4
    faulting = 0x041922A4
    результат = совпадает

    Непосредственная вызывающая функция sub_119FF70 строит адрес так:

    .text:011A0018                 lea     eax, [esi+edx]
    .text:011A001B                 imul    ecx, eax, 0CA4h
    .text:011A0021                 add     ecx, [ebx+1054h]
    .text:011A0027                 call    sub_119F670

    DMP подтверждает возврат после вызова 0x047C002C, то есть вызов
    по 0x011A0027. Регистры в точке исключения:

    EAX=0x000000B9  EDX=0x000000B8  ESI=0x00000001
    ECX=0x041922A4  EBX=0x001A86C0  EBP=0x001A7FC0

    Поля и локальные значения из сохранённой памяти:

    [EBX+370h] = 0x000000B8          начальный индекс 184
    [EBX+374h] = 0x00000000          выбранная запись
    [EBX+1054h] = 0x04100020         начало массива
    [EBX+1058h] = 0x04191600         конец массива
    [EBP-0Ch] = 0x000000B8           сохранённый начальный индекс
    [EBP-08h] = 0x000000B8           сохранённое число записей
    [ESP] = 0x047C002C               точный адрес возврата

    Размер массива и аварийный адрес:

    (0x04191600 - 0x04100020) / 0xCA4 = 184 записи
    допустимые индексы = 0..183
    0x04100020 + 184 x 0xCA4 = 0x04191600, конец массива
    0x04100020 + 185 x 0xCA4 = 0x041922A4, адрес исключения

    Таким образом, цикл уже начал вывод с позиции, равной числу записей.
    При ESI=0 он прочитал запись точно по указателю конца; эта память ещё
    оказалась читаемой. После inc esi цикл продолжился и при ESI=1 прочитал
    запись на один шаг 0xCA4 дальше конца, где страница уже недоступна.


4. Цепочка вызовов и контекст
-----------------------------

    Сокращённая цепочка по коду окна и фактическому адресу возврата:

    -> h3hota HD.exe A0_MapSelectDlg_Run_sub_584EC0
    -> h3hota HD.exe A0_WndMgr_Run_MapSelectDlg_sub_602D60
    -> h3hota HD.exe A0_DialogFunction_sub_5FFAC0
    -> HD_HOTA.dll sub_119FF70 - вывод строк каталога FM_Dir
    -> HD_HOTA.dll sub_119F670 - ВЫЛЕТ: чтение [ECX]

    sub_119F670 проверяет тип записи и сравнивает строку по смещению
    [+5C9h] с <HD3FMDir>\\. sub_119FF70 загружает FM_DirBk.pcx и
    FM_Dir.pcx. Вместе со стеком MapSelectDlg это относит сбой к списку
    файлов и каталогов окна выбора карты, а не к сетевому протоколу.

    В DMP есть несогласованность служебного номера потока: поток исключения
    указан как 10560, но ESP=0x001A7FA4 лежит в сохранённом диапазоне стека
    потока 20112. Поэтому Context и фактический адрес возврата используются
    как один источник, а текстовая цепочка вызовов - как отдельный источник.


5. Первопричина
---------------

    sub_119F3A0 вычисляет число записей как разность указателей начала и
    конца, делённую на 0xCA4. sub_119FF70 сохраняет это число, получает
    начальный индекс из поля [+370h] и запускает цикл видимых строк.

    Ошибка находится в условии цикла. Предел выбирается как минимум из
    числа видимых строк и общего числа записей. Сравнивается только ESI,
    тогда как индекс записи вычисляется как EDX+ESI. Проверки
    EDX+ESI < total_count перед умножением на 0xCA4 нет. После каждой
    строки выполняются inc esi, восстановление общего числа и начального
    индекса, затем без дополнительной проверки выполняется новый проход.

    В наблюдаемом состоянии total_count=184 и EDX=184. Значит, уже первый
    индекс 184 недопустим. Это не предположение о куче: начало, конец,
    число записей, начальный индекс и локальные значения одновременно
    сохранены в DMP, а арифметика полностью совпадает с ECX.

    Откуда поле [+370h] получило значение 184, установлено частично.
    Текстовый поиск нашёл прямую запись по 0x011A0354, но конкретная
    предшествующая последовательность действий пользователя не сохранена.
    Для исправления локального дефекта это не меняет обязательное условие:
    перед обращением нужно проверять сумму начального индекса и номера строки
    либо ограничивать число строк остатком total_count-start_index.

    Сравнение с оригиналом SoD: N/A - в падающей функции нет абсолютных
    вызовов к реализации SoD, а ресурсы FM_Dir и строка <HD3FMDir> относятся
    к собственной подсистеме HD-мода. Признаков копирования функции SoD нет.


6. Условия сбоя
---------------

    Доказанные условия наблюдаемого вылета:

    - открыто окно выбора карты, где HD-мод выводит список FM_Dir;
    - массив содержит 184 записи размером 0xCA4;
    - начальный индекс прокрутки равен 184, то есть числу записей;
    - цикл вывода продолжает хотя бы второй проход;
    - адрес второй недопустимой записи попадает в недоступную страницу.

    В журнале была сетевая игра, HotA 1.8.0, HD 5.7 R40 и карта
    Myth and Legend.h3m. Сетевая игра является контекстом обоих наиболее
    близких случаев, но код падающего цикла не ветвится по сетевому флагу.
    Поэтому обязательность сетевого режима не доказана.

    Вероятный, но не доказанный способ получить состояние - прокрутить длинный
    список, затем сменить каталог, фильтр или набор карт так, чтобы список
    сократился, а начальный индекс не был уменьшен. Это только план проверки,
    а не установленный факт.


7. Воспроизведение вылета
-------------------------

    1) Запустить HotA 1.8.0 с HD 5.7 R40 и открыть окно выбора карты.
    2) Подготовить список не менее чем из 184 записей и прокрутить его вниз.
    3) Изменить каталог или фильтр так, чтобы число записей стало равно
       начальному индексу прокрутки либо меньше него.
    4) Вызвать перерисовку списка.
    5) На входе sub_119FF70 проверить total_count и поле [+370h].
    6) Перед 0x011A0027 фиксировать EDX+ESI и требовать
       EDX+ESI < total_count.

    Контроль наблюдаемого случая: total_count=184, EDX=184, ESI сначала 0,
    затем 1; адреса равны 0x04191600 и 0x041922A4.

    Дифференциальная проверка исправления: ограничить start_index диапазоном
    0..total_count либо вычислять число выводимых строк как
    max(0, min(visible_rows, total_count-start_index)). После этого ни один
    вызов sub_119F670 не должен получать индекс 184 или больше при количестве
    184. Исчезновение вылета вместе с отсутствием таких вызовов подтвердит
    покрытие именно найденного дефекта.


8. Достоверность и ограничения
------------------------------

Подтверждено:

- TXT и DMP образуют одну точную пару; код, адрес, версия и Context совпадают.
- Адрес EIP переведён в RVA и IDA без расхождения; байты кода совпали.
- Эффективный адрес [ECX] машинно совпал с 0x041922A4.
- DMP сохранил begin=0x04100020, end=0x04191600, total_count=184,
  start_index=184 и фактический индекс 185.
- Точный адрес возврата 0x047C002C доказывает вызов из 0x011A0027.
- Хвост цикла содержит inc esi и без проверки EDX+ESI возвращается к условию,
  которое ограничивает только ESI.
- Проверены 11 статических точек вызова sub_119F670; фактическая точка
  выбрана по сохранённому стеку, а не по первой ссылке листинга.

Ограничения:

- Минидамп не содержит область 0x041922A4 и большую часть кучи; состояние
  самой недопустимой записи имеет статус not_captured.
- Служебный номер потока исключения не совпадает с диапазоном стека Context.
- Не восстановлена точная последовательность действий, записавшая 184 в
  поле [+370h]; известен прямой источник записи по 0x011A0354.
- У случая HD 5.7 RC11 нет DMP, поэтому его total_count и end неизвестны.

Отрицательные результаты:

- В mail-dumps/HD_HOTA.dll просмотрен 1261 физический TXT, распознано
  1260 журналов, после исключения 479 точных копий осталось 781 событие.
  Точного HD_HOTA.dll+0x19F670 и других 0x19Fxxx там нет.
- Во всём mail-dumps просмотрено 5418 TXT, распознано 5342 журнала,
  после исключения 1262 точных копий осталось 4080. Текущий адрес встречен
  один раз; другого 0x19Fxxx не найдено.
- В 30 доступных листингах межверсионная функция найдена по смысловой
  сигнатуре. Среди 912 уникальных вылетов HD_HOTA.dll в полном корпусе
  только два попали внутрь этой функции: текущий и случай HD 5.7 RC11.
- Полный регистровый признак текущего дефекта - ECX равен адресу чтения,
  ESI=1, EAX=EDX+1, EBX-EBP=0x700 и EBX-ESP=0x71C - найден только здесь.
- 246 журналов проходят через общий MapSelectDlg, но не имеют этого
  регистрового признака; общий экран сам по себе не делает их связанными.

Вероятно связанный случай:

    mail-dumps/HD_HOTA.dll/
    HD_HOTA.dll+0x14F1E0-1.8.0-1-97CAD.txt

    HD 5.7 RC11, HotA 1.8.0. RVA 0x14F1E0 соответствует той же функции
    sub_114F1E0; первый кадр - её межверсионная вызывающая функция
    sub_114FAE0. Код вычисляет ECX как base+(EDX+ESI)*0xCA4, стек также
    проходит через MapSelectDlg. Регистры: EDX=0x98, ESI=0,
    EAX=0x98, ECX=0x14E2FC60, и ECX равен адресу неудавшегося чтения.
    Это сильная связь по функции и подсистеме, но без DMP нельзя доказать,
    что 0x98 равен числу записей. Случай не включён в подтверждённую семью
    и не перемещён.

Проверка полноты статического разбора:

    1. Адресная арифметика: закрыта, все значения совпали.
    2. Точки вызова: перечислены все 11, фактическая доказана.

    4. Потребители: универсальный вывод о всех путях не делается; разобран

    5. Выделение памяти: N/A - в падающей функции выделения нет.

    7. След SoD: не найден; собственный код HD-мода.

    10. Условие активации: экран доказан, точное действие не установлено.

Признаки поиска в старых версиях HotA / в SoD:

- функция начинается с cmp dword ptr [ecx],0 и использует строку
  <HD3FMDir>\\ по адресу записи [+5C9h];
- вызывающая функция загружает FM_DirBk.pcx и FM_Dir.pcx;
- адрес записи строится как begin+(start_index+row)*0xCA4;
- стек содержит A0_DialogFunction_sub_5FFAC0,
  A0_WndMgr_Run_MapSelectDlg_sub_602D60 и A0_MapSelectDlg_Run_sub_584EC0;
- для того же дефекта нужны доказанные start_index >= total_count и
  отсутствие проверки суммы перед обращением;
- в доступном коде SoD такой функции не установлено.


ВЫВОД
-----

    В HD_HOTA.dll+0x19F670 доказан выход за границы массива записей окна
    выбора карты. sub_119FF70 ограничивает номер видимой строки, но не
    проверяет start_index+row против total_count. При 184 записях и
    start_index=184 код дошёл до индекса 185 и прочитал 0x041922A4.
    Рекомендуемое исправление для HD-мода: ограничивать начальный индекс после изменения
    списка и перед каждым вызовом проверять составной индекс либо считать
    число строк от остатка total_count-start_index. Случай HD 5.7 RC11
    считать вероятно связанным до получения DMP или повторения под отладчиком.
