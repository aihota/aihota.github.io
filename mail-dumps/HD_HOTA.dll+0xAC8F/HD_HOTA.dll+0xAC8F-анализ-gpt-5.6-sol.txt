АНАЛИЗ ВЫЛЕТА  HD_HOTA.dll+0xAC8F  (интерфейс карты приключений: панели портретов героев)
================================================================================

    Модель: GPT-5.6 Sol
    Дата:   14.08.2026
    Заключение: HD_HOTA.dll прочитал portrait_id через невалидный
    вычисленный указатель; верхняя проверка hero_id отсутствует, но
    испортивший адрес входной член в целевом событии не установлен.


КРАТКОЕ РЕЗЮМЕ
--------------

    Вылет произошёл в HD_HOTA.dll+0xAC8F, внутри sub_100AB80+0x10F.
    Инструкция movzx ecx, byte ptr [ecx+34h] читает поле portrait_id
    объекта героя. В момент сбоя ECX=0xBBA18300, поэтому адрес чтения
    равен 0xBBA18334. Он точно совпадает с адресом из исключения.

    В HD 5.7 R40 указатель вычисляется по фактической формуле
    hero_id * 0x492 + [0x0041C6B5] + [0x00699538]. hero_id берётся из
    Player::heroes_ids. Код отбрасывает только 0xFFFFFFFF, но не проверяет
    верхнюю границу ID. Невалидность итогового указателя и отсутствие
    проверки доказаны; целевой минидамп не сохраняет все три входных
    слагаемых, поэтому приписывать порчу только hero_id нельзя.

    Это не единичный адресный вариант. Во всём корпусе найдены 32
    SHA-уникальных инцидента той же функции в разных версиях HD-мода.
    Они представлены 90 физическими TXT-копиями. В прежней плоской папке
    mail-dumps/HD_HOTA.dll было 30 уникальных инцидентов среди 58 TXT;
    ещё один старый инцидент находится в серии 0xA91F, а 32-й является
    текущим 0xAC8F. Все 32 события сетевые, содержат Me: ERROR, имеют
    арифметику ECX+0x34 и верхний кадр hota.dll+0xB05B2. Me: ERROR является
    корреляцией, а не доказанной первопричиной.

2. Проверка листинга и адреса
-----------------------------

    Runtime-база HD_HOTA.dll равна 0x045E0000. Сложение базы и RVA
    0xAC8F даёт 0x045EAC8F, то есть CONTEXT.EIP целевого минидампа.
    При imagebase 0x01000000 адрес в IDA равен 0x0100AC8F.

    Точка входит в sub_100AB80, диапазон 0x0100AB80..0x0100B267.
    Версия листинга совпадает с HD 5.7 R40. TimeDateStamp равен
    0x6A7C2AD0, SizeOfImage равен 0x011F9000. SHA-256 PE из заголовка
    листинга:

    B2E45E452C6F96EE1272D571BC663C76FD2BEAA936790BECFC999E5424033138

    .text:0100AC8F  movzx   ecx, byte ptr [ecx+34h]

    В памяти дампа по 0x045EAC8F находятся байты 0F B6 49 34, то есть
    та же инструкция. Подстановка другой версии листинга не требовалась.

    sub_100AB80 зарегистрирован как перехват оригинального адреса
    0x00403560. Во всех 30 доступных листингах HD_HOTA.dll обнаружены
    тот же перехват и семантически эквивалентное чтение portrait_id.
    Для 5.7 R12/R13/R17/R18 эквивалент находится по 0xA67C, для 5.7
    R35 по 0xABEF, для 5.7 R36-R39 по 0xAC5F. Корпусных логов по этим
    трём вариантам не найдено.


3. Точка сбоя
-------------

    Инструкция читает один байт поля hero->portrait_id по смещению
    [+34h]. Значения в аварийном контексте:

    EIP              0x045EAC8F
    ECX              0xBBA18300
    ECX + 0x34       0xBBA18334
    Адрес исключения 0xBBA18334
    EDI              0x00000000
    EBP              0x001A9D74
    ESP              0x001A9D64

    Равенство ECX + 0x34 = 0xBBA18334 однозначно связывает исключение
    с этой инструкцией. Невалиден уже вычисленный указатель героя в
    ECX, а не таблица ресурсов портретов, которая используется позже.

    Фактическая последовательность HD 5.7 R40:

    .text:0100ABC5  mov     eax, [esi+edi*4+8]
    .text:0100ABCA  cmp     eax, 0FFFFFFFFh
    .text:0100ABE6  imul    eax, 492h
    .text:0100ABF2  add     eax, ds:41C6B5h
    .text:0100ABF8  add     eax, ds:699538h
    .text:0100ABFE  mov     [ebp+arg_8], eax
    .text:0100AC8A  mov     ecx, [ebp+arg_8]
    .text:0100AC8F  movzx   ecx, byte ptr [ecx+34h]

    Поэтому для этой сборки:

    hero_ptr = hero_id * 0x492 + [0x0041C6B5] + [0x00699538]

    hero_id поступает из Player::heroes_ids. Перед вычислением проверяется
    только hero_id == 0xFFFFFFFF. Проверки максимального допустимого ID
    нет. Значения hero_id и обоих базовых слагаемых в целевом аварийном
    снимке вместе не сохранены.


4. Цепочка вызовов и контекст
-----------------------------

-> hota.dll!sub_100B0520+0x92 (hota.dll+0xB05B2)
-> patcher_x86.dll+0x11410 (исполнение цепочки перехватов)
-> HD_HOTA.dll!sub_100B270 (перехват SoD 0x004032E0)
-> HD_HOTA.dll!sub_100AB80+0x10F - ВЫЛЕТ: чтение [ECX+34h]

    sub_100B270 заменяет A0_AdvMgrDlg_SetHeroListShow_Position_sub_4032E0,
    а sub_100AB80 заменяет A0_AdvMgr_UpdateHeroPort_sub_403560. Обе
    функции относятся к обновлению списка и портретов героев на карте
    приключений. Возвратный адрес перехвата равен 0x02C72AE9; сохранённый
    указатель Player равен 0x09B30968.

    Одинаковый верхний кадр hota.dll+0xB05B2 присутствует во всех 32
    уникальных инцидентах семьи, поэтому адресные варианты не являются
    случайным совпадением одного операнда.


5. Первопричина
---------------

    Непосредственная причина вылета - чтение [+34h] через уже
    невалидный hero_ptr. Доказанный защитный дефект - отсутствие верхней
    проверки hero_id до вычисления адреса. HD_HOTA.dll получает Player
    через A0_GameMgr_GetMe_AsPlayer_sub_4CE670, читает ID из
    Player::heroes_ids, исключает только 0xFFFFFFFF и умножает ID на
    размер структуры 0x492.

    Возможны три более ранних источника плохого итогового адреса:

    1) В сетевой ветке A0_GameMgr_GetMe_AsPlayer_sub_4CE670 использует
       A0_MeAtGameStart_dword_6995A4 без проверки диапазона 0..7. Если
       глобал неверен, функция возвращает не того Player.
    2) Указатель Player верен, но одна из записей Player::heroes_ids
       повреждена либо не инициализирована.
    3) Повреждено одно из базовых слагаемых R40: значение по
       0x0041C6B5 либо A0_GameMgr_dword_699538.

    В листинге h3hota.exe найдено 30 обращений к
    A0_MeAtGameStart_dword_6995A4 и пять прямых писателей по адресам
    0x0045B61F, 0x004EF4F0, 0x004EFBBB, 0x00588754 и 0x005887E7.
    Состояние этих путей и всех слагаемых в момент вылета отсутствует
    в минидампе, поэтому выбрать один из трёх источников невозможно.
    Утверждение о use-after-free данными не подтверждается.

    Оригинальная A0_AdvMgr_UpdateHeroPort_sub_403560 в SoD использует
    отдельную формулу GameMgr + 0x21620 + ID * 0x492: берёт ID из
    heroes_ids, сравнивает только с 0xFFFFFFFF и читает байт [+34h].
    Формулы R40 и SoD нельзя подменять друг другом, но защитный дефект
    верхней проверки присутствует в обеих реализациях.


6. Условия сбоя
---------------

    Необходимы одновременно следующие условия:

    1) выполняется обновление видимого слота панели героя;
    2) выбранный элемент Player::heroes_ids не равен 0xFFFFFFFF;
    3) значение не соответствует допустимому элементу массива героев;
    4) код доходит до чтения portrait_id по вычисленному указателю.

    Все 32 уникальных события семьи имеют Network Game = 1 и строку
    Me: ERROR. В девяти логах присутствует блок Comment, но ни в одном
    нет непустого пользовательского комментария. Поэтому конкретное
    действие игрока по комментариям восстановить нельзя.

    Производный AUTOSAVE распаковывается как H3SVG, формат 10, содержит
    двух игроков и карту
    wlin0005,lqq077 2026.08.13 03;48 {Default}.h3m. Это подтверждает
    сетевой контекст целевого случая, но не доказывает, что сохранение
    уже содержит плохой ID: AUTOSAVE создан после сбоя и проверен лишь
    частично.


7. Воспроизведение вылета
-------------------------

    Выполнен безопасный одноразовый прогон HD 5.7 R40 под WineDbg.
    Использовались два сетевых клиента: отладочный клиент из папки 180
    загружал целевое сохранение, второй обычный клиент обеспечивал
    сетевую сессию. Роли клиентов и порядок остановки были сохранены в
    каталоге прогона.

    В HD_HOTA.dll на диске временно заменены байты 0F B6 49 34 на
    CC B6 49 34 по RVA 0xAC8F. До запуска проверены исходная SHA-256 и
    якорные байты, после завершения DLL восстановлена до исходной
    SHA-256. В памяти отладочного клиента по 0x025EAC8F подтверждён int3;
    дополнительных точек WineDbg не было.

    Целевой AUTOSAVE был загружен. Выбор героев и доступные действия не
    вызвали естественный вылет и не исполнили целевой int3. Итог прогона
    классифицирован машинно как armed_not_reached: ловушка доказанно
    вооружена, но исследуемый путь за выполненный сценарий не достигнут.

    Перед завершением снят один финальный снимок памяти. Наблюдались:

    A0_MultiplayerMode               2
    A0_MeAtGameStart                 0
    A0_GameMgr                       0x01D00000
    A0_Current_Player_ID             0
    [0x0041C6B5]                     0x06A90000
    локальный Player                 0x01D20AD0
    локальные heroes_ids             202, 211, 177, 200, 30, 208, -1, -1
    второй Player                    0x01D20C38
    второй список heroes_ids         21, 165, 79, 123, 70, 143, 22, 26
    Hero*(202)                       0x087C9B34
    Hero*(211)                       0x087CC456

    Эти значения допустимы и согласуются с формулой R40. Плохое
    состояние в завершённом прогоне не наблюдалось. Адрес 0xFCFC0ED0 в
    финале создан парой Ctrl-C для остановки отладчика; это искусственный
    останов, а не естественный вылет и не член исследуемой семьи.

    Узкий отрицательный вывод: приложенный AUTOSAVE и выполненная
    последовательность выбора героев не привели к исследуемой ветке.
    Прогон не опровергает кратковременную сетевую гонку, состояние другого
    клиента либо иной путь обновления Player::heroes_ids.

    Следующий измерительный прогон должен идти по ступеням:

    1) заранее сохранить topology.json с ролями клиентов, путями, PID,
       Wine PID, хостом, загрузчиком сохранения и порядком остановки;
    2) без остановок посчитать прохождения sub_100AB80 и целевой ветки;
    3) вести кольцевой журнал Player, слота, hero_id, обоих базовых
       слагаемых, hero_ptr и адреса возврата;
    4) только после первого плохого значения наблюдать пять источников
       записи A0_MeAtGameStart и источники записи Player::heroes_ids.


8. Достоверность и ограничения
------------------------------

Подтверждено:

- Точный EIP, адрес чтения, регистры и четыре байта инструкции.
- Совпадение версии PE и листинга HD 5.7 R40.
- Последовательность R40 и формула hero_id * 0x492 +
  [0x0041C6B5] + [0x00699538].
- Назначение поля [+34h] как portrait_id и невалидность итогового
  указателя в целевом вылете.
- Отсутствие верхней проверки hero_id в HD_HOTA.dll и в SoD; формула
  SoD при этом отдельно равна GameMgr + 0x21620 + ID * 0x492.
- Единая межверсионная семья из 32 SHA-уникальных инцидентов; локальная
  публикуемая серия содержит 31 из них, внешняя серия 0xA91F - ещё один.
- Успешный перенос 58 TXT и двух DMP по проверенному манифесту.
- В живом прогоне целевой int3 был вооружён, DLL затем восстановлена,
  а снятые значения двух игроков и выбранных героев были допустимыми.

Ограничения:

- MiniDumpNormal содержит 45 диапазонов и 54 848 байт памяти.
  Memory64List отсутствует, область 0xBBA18300 в дамп не вошла.
- Значения hero_id, [0x0041C6B5] и [0x00699538] целевого вылета не
  сохранены вместе. Нельзя доказанно выбрать испорченное слагаемое.
- Одноразовый сетевой прогон не достиг sub_100AB80+0x10F и не
  воспроизвёл естественный вылет; последний источник записи не найден.
- Финальный адрес 0xFCFC0ED0 относится к искусственному Ctrl-C и не
  характеризует исследуемый механизм.
- Для части старых версий нет точного листинга. Их связь основана на
  совпадении регистров, адресной формы, позиции в обработчике, стека и
  общего перехваченного адреса SoD.
- Причинная роль Me: ERROR не доказана; это общий признак корпуса.

Отрицательные результаты:

- Точный HD_HOTA.dll+0xAC8F найден в одном логе. Поиск выполнен по всем
  3557 TXT, распознанным как журналы вылета; контрольный образец -
  текущий лог HD 5.7 R40.
- Совпадений широкой сигнатуры ECX+0x34 и hota.dll+0xB05B2 вне
  сопоставленной семьи: 0 среди 32 уникальных совпадений.
- Непустых пользовательских Comment: 0 в девяти имеющихся блоках.
- Логов по эквивалентным RVA 0xA67C, 0xABEF и 0xAC5F: 0.
- Признаков собственной аллокации либо виртуального вызова в падающей
  функции не найдено; гипотезы ошибки размера аллокации и неверной
  vtable к этому месту неприменимы.
- В сетевом прогоне плохих значений не наблюдалось, но покрытие целевой
  ветки равно нулю; это ограничение сценария, а не опровержение дефекта.

Отозванные версии:

- Ранее формула GameMgr + 0x21620 + ID * 0x492 была приписана одновременно
  R40 и SoD. Точный листинг R40 это опровергает. Формула сохранена только
  для SoD; для R40 указаны два фактических базовых слагаемых.
- Ранее невалидный адрес был приписан исключительно плохому hero_id.
  Отсутствие всех входных слагаемых в целевом минидампе не позволяет
  выбрать между ID, выбором Player и повреждением базового значения.
  В силе остаются невалидность hero_ptr и отсутствие верхней проверки ID.


ВЫВОД
-----

    Виновная точка - HD_HOTA.dll+0xAC8F. В HD 5.7 R40 обработчик
    получает hero_id из Player::heroes_ids, проверяет только 0xFFFFFFFF,
    вычисляет hero_ptr как hero_id * 0x492 + [0x0041C6B5] +
    [0x00699538] и читает portrait_id по [+34h]. В целевом событии
    итоговый hero_ptr невалиден, а адрес чтения точно совпадает с адресом
    исключения.

    Рекомендуемое исправление: проверять индекс локального игрока, hero_id
    и принадлежность вычисленного адреса фактическому хранилищу героев до
    чтения [+34h]; при неверном значении переводить слот в пустое
    состояние. Отдельное наблюдение пяти источников записи
    A0_MeAtGameStart_dword_6995A4, источников Player::heroes_ids и двух
    базовых слагаемых нужно для поиска первичного места порчи.

    Один завершённый сетевой прогон подтвердил вооружение целевой ловушки
    и допустимое живое состояние, но не достиг исследуемой ветки. Поэтому
    он не воспроизвёл дефект и не позволяет исключить кратковременное
    сетевое состояние. Доказаны непосредственная точка, невалидный
    итоговый указатель и отсутствие верхней проверки; конкретное
