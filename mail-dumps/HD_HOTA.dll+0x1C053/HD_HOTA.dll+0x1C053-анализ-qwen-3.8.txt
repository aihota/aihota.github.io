================================================================
АНАЛИЗ ВЫЛЕТА HD_HOTA.dll+0x1C053 (отрисовка миникарты)
================================================================

Модель: Qwen 3.8
Дата: 02.08.2026
Заключение: HD-мод воспроизводит логику миникарты SoD
(A0_AdvMgr_Draw_Minimap): case 98 использует значение
A0_MapCell_GetSetup как индекс массива городов без проверки
типа объекта клетки — при герое или корабле индекс выходит
за границы массива. Дефект унаследован из движка SoD.

КРАТКОЕ РЕЗЮМЕ
--------------
Игра падает при отрисовке миникарты. HD-мод замещает функцию
миникарты SoD (A0_AdvMgr_Draw_Minimap_sub_412BA0) собственной
версией (sub_101AE10 в R33; sub_101B0E0 в R35). Для case 98
таблицы переходов код берёт foreground-клетку и читает её
«setup»-значение функцией A0_MapCell_GetSetup. Это значение
используется как индекс в массиве городов (поле
game_state+0x21614, шаг элемента 0x168 = 360 байт), а
прочитанный байт — как индекс цвета в 16-битной палитре
(A0_GamePal_16, 0x6AAD18).

Оригинальный код SoD по адресу 0x412F7D делает ровно то же
самое, без проверки границ. HD-мод воспроизводит логику
движка, включая дефект.

GetSetup возвращает индекс города только для клетки с городом;
для клетки с героем (тип 34) возвращается значение miu_setup
героя, для корабля (тип 8) — индекс корабля. Эти значения не
имеют отношения к массиву городов и многократно превышают его
размер (наблюдаемые индексы: 91, 107, 141, 167, 173 при
типичном числе городов на карте до 48).

Пять дампов на пяти версиях HD-мода (R23, R29, R33, R34, R35)
падают на одной и той же инструкции, побайтно идентичной во
всех сборках. Все пять — сетевые партии на карте приключений.
Дефект стабилен между версиями: функция смещается по образу
(sub_1019F80 -> sub_101AC10 -> sub_101AE10 -> sub_101B0E0),
но код case 98 не меняется. Текущий адрес серии — +0x1C053
(R35); прежние адреса +0x1AEF3 / +0x1BB83 / +0x1BD83 — те же
инструкции в сборках R23 / R29 / R33-R34.

5. Первопричина
---------------
Виновный модуль: HD_HOTA.dll (HD-мод), воспроизводит логику
h3hota.exe (A0_AdvMgr_Draw_Minimap_sub_412BA0). Виновная
функция: sub_101B0E0 (R35) / sub_101AE10 (R33, R34) /
sub_101AC10 (R29) / sub_1019F80 (R23), case 98 таблицы
переходов (jpt_101BFA7 в R35; jpt_101BCD7 в R33).

Case 98 предполагает, что foreground-клетка всегда содержит
город, и результат GetSetup — индекс города. Но foreground-
клетка может содержать героя (тип 34), корабль (тип 8) или
другой объект.

Поставщик данных — A0_MapCell_GetSetup (h3hota.exe, 0x4FD280)
возвращает разные значения в зависимости от типа объекта:

    .text:004FD280  mov  eax, [ecx+1Eh]   ; object_type
    .text:004FD283  cmp  eax, 22h          ; тип 34 = герой
    .text:004FD286  jnz  short loc_4FD2B0
    ; для героя: возвращает hero_astr21620[setup].miu_setup
    .text:004FD2A5  lea  eax, [ecx+eax*2+21620h]
    .text:004FD2AC  mov  eax, [eax+14h]   ; miu_setup героя
    .text:004FD2AF  retn
    ; для корабля (тип 8): индекс из boats_4dword4E3C1
    .text:004FD2B5  mov  ecx, [ecx]
    .text:004FD2C5  mov  eax, [ecx+edx*8+14h]
    .text:004FD2C9  retn
    ; для остальных: setup_dword0 клетки
    .text:004FD2CA  mov  eax, [ecx]
    .text:004FD2CC  retn

Для героя возвращается miu_setup (произвольное число), для
корабля — индекс корабля. Эти значения не ограничены размером
массива городов. Массив городов по адресу [game_state+0x21614]
содержит не более ~48 элементов (ограничение числа городов на
карте). Наблюдаемые индексы 91, 107, 141, 167, 173 многократно
превышают этот предел, и чтение выходит за границы выделения.

Дефект унаследован из движка SoD. Оригинальный код
A0_AdvMgr_Draw_Minimap (h3hota.exe, 0x412F7D-0x412FC1)
функционально идентичен и тоже не проверяет границы:

    .text:00412F7D  mov  ax, [ebx+0Ch]    ; case 98
    .text:00412F81  test al, 40h
    .text:00412F8E  call A0_MapCell_Get_Fore_Cell_sub_4FD0F0
    .text:00412F95  test eax, eax
    .text:00412F9F  call A0_MapCell_GetSetup_sub_4FD280
    .text:00412FAA  lea  eax, [eax+eax*4]     ; * 5
    .text:00412FAD  mov  edx, [ecx+21614h]    ; towns_list
    .text:00412FB9  lea  eax, [eax+eax*8]     ; * 45
    .text:00412FBC  movsx eax, byte ptr [edx+eax*8+1] ; *360+1
    .text:00412FC1  mov  si, [ecx+eax*2+9Ch]  ; палитра

HD-мод воспроизводит логику движка, включая отсутствие
проверки границ индекса.

Доказательная база (родственные функции). Соседние case
(42/53, 17/20, 33, 87) используют тот же паттерн
(Get_Fore_Cell -> GetSetup -> индекс в массиве), но обращаются
к другим массивам ([game_state+0x4E38C], [game_state+0x4E39C],
[game_state+0x4E3AC]) с другими шагами. Ни один из этих путей
не проверяет границы.

Плавающие адреса +0x1BD83 (R33/R34), +0x1BB83 (R29),
+0x1AEF3 (R23) — тот же дефект (данный отчёт, дампы 1-4);
серия переименована на +0x1C053 (R35) по актуальной версии.
Отличать от других вылетов подсистемы отрисовки:
HD_HOTA.dll+0x1B107B — другой дефект (NULL-разыменование при
отказе конструктора поверхности Pcx16; механизм, регистры,
стек полностью различны). HD_HOTA.dll+0x1AFF9 — другой дефект
(EBX = 0x220, не case 98; ESI != 0x699538). Семейство
аллокатора HD_HOTA.dll+0x1A0E — другой дефект (отказ
operator new -> NULL -> memset/memcpy по NULL; общий корень
«давление на кучу», но другой механизм и место сбоя).

6. Условия сбоя
---------------
Обязательные условия:
    - Сетевая или одиночная игра на карте приключений
    - Обработка case 98 (EBX = 0x62) в HD-моде
    - Foreground-клетка содержит объект НЕ город
      (герой, корабль, декоративный объект)
    - Результат GetSetup превышает размер массива городов

Наблюдаемые условия:
    - Все 5 дампов: сетевая игра (Network Game = 1)
    - День 1-4 — активная фаза игры с героями на карте
    - Graphics.Mode: 5 и 7 — не влияет на механизм
    - Карты: разные (5 карт в 5 дампах) — не зависит
      от конкретной карты

Условие активации пути:
    - Запустить сетевую или одиночную игру на карте
      с несколькими городами и героями
    - Дождаться обработки case 98 HD-модом (событие
      карты приключений, связанное с декоративными
      объектами — точный триггер определяется
      содержимым клетки)

Базовый сценарий:
    - Сетевая партия, 2+ игроков
    - Карта с городами и героями, активно
      перемещающимися по карте
    - День 3-4 (герои рядом с городами и
      декоративными объектами)

Варьирование:
    - Graphics.Mode: не влияет (наблюдались 5 и 7,
      в падающем коде нет ветвления по режиму)
    - Версия HD-мода: дефект стабилен (R23, R29, R33, R34, R35)
    - Карта: не зависит (5 разных карт в 5 дампах)

Дифф-тест:
    - Сравнить поведение case 98 при foreground-клетке
      с городом vs с героем: для города GetSetup вернёт
      допустимый индекс, для героя — miu_setup (выход
      за границы)

8. Достоверность и ограничения
------------------------------
Подтверждено:
- Инструкция краха и адресная арифметика —
  совпадение по всем 5 дампам
- Побайтная идентичность кода case 98 в пяти сборках
  (R23, R29, R33, R34, R35) — функция смещается, код не меняется
- Регистровые инварианты: EBX=0x62, ESI=0x699538 —
  стабильны по всем дампам
- Массив [game_state+0x21614] — массив городов (подтверждено
  по h3hota.exe: stride 0x168, вызов A0_Town_GetTypeName,
  имя towns_list_4dword21610)
- A0_MapCell_GetSetup возвращает НЕ индекс города для
  объектов типа 34 (герой) и 8 (корабль) — прочитано
  в листинге h3hota.exe (0x4FD280-0x4FD2CC)
- Соседние case (42/53, 17/20, 33, 87) используют тот же
  паттерн без проверки границ — прочитано в листинге R33
- sub_101AE10 (R33) / sub_101B0E0 (R35) — замена
  A0_AdvMgr_Draw_Minimap (хук на 0x412BA0; регистрация
  в sub_1034EC0+2991 в R33, в sub_1035190+2ADD в R35)
- Оригинальный код SoD (0x412F7D-0x412FC1) содержит
  функционально идентичный паттерн без проверки границ
- 0x6AAD18 = A0_GamePal_16 (16-битная палитра),
  byte_1 структуры города = индекс цвета для миникарты

Ограничения:
- Минидампы сокращённые (без кучи): содержимое массива
  городов и точный тип объекта на foreground-клетке
  не проверялись — определение типа объекта (герой/корабль)
  выведено из значений индекса и кода GetSetup
- Логи SoD (без HD-мода) не проверялись: оригинальный
  код A0_AdvMgr_Draw_Minimap содержит тот же дефект,
  но подтверждений вылета в чистом SoD нет
- Нет данных по версиям HotA до 1.8.0: все 5 дампов сняты
  на HotA 1.8.0, наличие дефекта в более старых версиях
  HotA не проверялось
- Полный аудит всех 189+ case таблицы переходов
  не проводился; проверены case 98, 42/53, 17/20, 33, 87

ВЫВОД
-----
Вылет HD_HOTA.dll+0x1C053 (и плавающие адреса +0x1BD83,
+0x1BB83, +0x1AEF3 в сборках R33/R34, R29, R23) — выход за
границы массива городов при отрисовке миникарты.

HD-мод замещает функцию миникарты SoD (A0_AdvMgr_Draw_
Minimap_sub_412BA0) собственной версией (sub_101AE10 в R33;
sub_101B0E0 в R35). Case 98 таблицы переходов получает
foreground-клетку и вызывает A0_MapCell_GetSetup, результат
которого используется как индекс массива городов, а
прочитанный байт — как индекс цвета в палитре. GetSetup
возвращает индекс города только для клетки с городом; для
героя (тип 34) возвращается miu_setup героя, для корабля
(тип 8) — индекс корабля. Эти значения не ограничены
размером массива городов, и при достаточно большом значении
чтение выходит за границы выделения.

Дефект унаследован из движка SoD: оригинальный код
A0_AdvMgr_Draw_Minimap (h3hota.exe, 0x412F7D-0x412FC1)
содержит функционально идентичный паттерн без проверки
границ. HD-мод воспроизводит логику движка.

Дефект присутствует минимум в пяти версиях HD-мода
(R23, R29, R33, R34, R35) и не зависит от графического
режима, конкретной карты или числа игроков. Все наблюдаемые
вылеты — в сетевой игре на карте приключений. Наблюдаемые
индексы: 91, 107, 141, 167, 173 — все многократно превышают
типичное число городов на карте (до 48). Серия переименована
на +0x1C053 по актуальной версии (R35); дамп 5 (R35, индекс
173) добавлен к четырём ранее разобранным.
