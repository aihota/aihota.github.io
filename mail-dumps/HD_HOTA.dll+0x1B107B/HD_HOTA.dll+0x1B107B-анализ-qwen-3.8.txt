АНАЛИЗ ВЫЛЕТА HD_HOTA.dll+0x1B107B (отрисовка интерфейса)
================================================================

Модель: Qwen 3.8
Дата: 28.07.2026
Заключение: HD-мод: конструктор поверхности вернул NULL
при отказе выделения памяти, вызывающий код не проверил
результат и упал при чтении поля объекта.

КРАТКОЕ РЕЗЮМЕ
--------------
Игра сохраняла копию экрана (поверхности отрисовки) при
отрисовке интерфейса онлайн-лобби. Конструктор поверхности
запросил у системы пиксельный буфер размером около 5 МБ,
получил отказ и вернул нулевой указатель. Вызывающая функция
не проверила результат и сразу обратилась к полю объекта
по смещению 0x1C от нуля — чтение адреса 0x0000001C вызвало
исключение доступа.

Родственные функции того же модуля проверяют результат
конструктора на NULL; падающая функция — единственная,
где проверка пропущена.

5. Инструкция краша и адресная проверка
---------------------------------------

    .text:011B107B  push dword ptr [esi+1Ch] ; Size

Адресная проверка:

Механика отказа. Функция sub_11B1050 создаёт копию текущей
поверхности отрисовки и копирует пиксельные данные вызовом

    .text:011B105F  mov  edx, [eax+40h]

Конструктор sub_11B6EC0 вернул NULL (EAX = 0), значение
перенесено в ESI. Проверка на NULL отсутствует, и команда
push читает поле «размер буфера» по смещению 0x1C от нуля.

7. Анализ регистров и группировка
---------------------------------
EAX = ESI = 0 — нулевой результат конструктора поверхности
sub_11B6EC0. Оба регистра совпадают, потому что sub_11B1050
переносит EAX в ESI (mov esi, eax на 0x11B1073).

ECX = 0x21985088 — указатель на исходную поверхность
(объект в куче, поле +0x40 глобала 6992D0h). Адрес лежит
в допустимом диапазоне кучи 32-битного процесса — исходная
поверхность, скорее всего, жива и содержит корректные
размеры.

EDI = 0x65 (101) — аргумент диспетчера лобби sub_107FAD0
(сравнение cmp edi, 65h на 0x107FADD). Код действия
интерфейса.

EBX = 0x001A9F2C, ESP = 0x001A9D68, EBP = 0x001A9D70 —
указатели стека, штатные значения.

8. Первопричина
---------------
Конструктор поверхности sub_11B6EC0 (IDA 0x11B6EC0) создаёт
объект поверхности: выделяет заголовок размером 0x38 байт
и буфер пикселей размером stride * height. При отказе любого
из двух выделений конструктор возвращает NULL:

    .text:011B6EE6  call eax              ; operator new(0x38)
    .text:011B6EED  test edi, edi
    .text:011B6EEF  jz   loc_11B6F6A     ; NULL — возврат 0

    .text:011B6F53  call eax              ; operator new(размер)
    .text:011B6F5B  test eax, eax
    .text:011B6F5D  jnz  loc_11B6F75     ; успех
    .text:011B6F5F  push edi             ; освободить заголовок
    .text:011B6F65  call eax             ; operator delete
    ; возврат NULL (loc_11B6F6A: xor eax, eax; retn 4)

Для Graphics.Mode = 7 (32-битная внутренняя отрисовка)
и разрешения 1486x836 размер пиксельного буфера:
    stride = 1486 * 4 = 5944 байта
    буфер = 5944 * 836 = 4 969 184 байта (около 4,7 МБ)

В 32-битном процессе с ограниченным адресным пространством
выделение почти 5 МБ может завершиться отказом при
фрагментации или исчерпании памяти.

Сравнение с родственными функциями. Два других вызывающих
кода того же конструктора проверяют результат на NULL:

1) sub_11B0FD0 (IDA 0x11B0FD0, соседняя функция сохранения):

    .text:011B0FF0  call sub_11B6EC0
    .text:011B0FF5  mov  edx, eax
    ...
    .text:011B1014  test edx, edx
    .text:011B1016  jz   locret_11B104B  ; NULL — выход

2) Код в sub_10091A6:

    .text:010091A6  call sub_11B6EC0
    .text:010091AB  mov  ecx, eax
    .text:010091B0  test ecx, ecx
    .text:010091B2  jz   loc_100920C     ; NULL — обработка

Падающая функция sub_11B1050 — единственная из проверенных,
где проверка на NULL после вызова конструктора отсутствует.
Это конкретный дефект логики: авторы знали о возможности
нулевого возврата (две другие точки проверяют), но в этой
ветке проверка потеряна.

11. Воспроизведение вылета
--------------------------
Вылет недетерминирован: зависит от состояния кучи
32-битного процесса в момент выделения памяти.

Условие активации пути: отрисовка интерфейса онлайн-лобби
(sub_107FAD0, код действия EDI = 0x65), при которой
вызывается сохранение поверхности (sub_11B1050).

Вероятностный путь:
    1) Запустить игру с Graphics.Mode = 7 и высоким
       разрешением (1486x836 или выше).
    2) Войти в интерфейс онлайн-лобби (h3lobby).
    3) Повторять вход/выход из лобби, чтобы спровоцировать
       накопление копий поверхностей в стеке сохранения
       и фрагментацию адресного пространства.
    4) Вылет произойдёт, когда operator new не сможет
       выделить буфер около 5 МБ.

Дифференциальный тест:
    Graphics.Mode = 0 или 1 (16-битная внутренняя
    отрисовка) уменьшает размер буфера вдвое (около 2,4 МБ),
    что снижает вероятность отказа. Если при 16-битном
    режиме вылет не воспроизводится, а при 32-битном
    появляется — это подтверждает диагноз отказа выделения.

Среда: 32-битный процесс, Windows, HD-мод 5.7 R33,
HotA 1.8.0.

Достоверность и ограничения
----------------------------
Подтверждено:
- Листинг HD_HOTA.dll-5.7 R33 верифицирован по entry point
  (DllEntryPoint на 0x11C4547 совпадает с логом).
- Адресная проверка сошлась: ESI (0) + 0x1C = 0x1C =
  faulting address.
- Конструктор sub_11B6EC0 возвращает NULL при отказе
  operator new — прочитано в дизассемблере.
- Родственные функции (sub_11B0FD0, код в sub_10091A6)
  проверяют результат на NULL — прочитано в дизассемблере.
- sub_11B1050 не проверяет результат — прочитано
  в дизассемблере.

Ограничения:
- Единственный дамп: нет корреляции по нескольким вылетам.
- Минидамп сокращённый (без кучи): невозможно проверить,
  какие размеры хранила исходная поверхность (ECX=0x21985088)
  и какое именно выделение отказало (заголовок 0x38 байт
  или пиксельный буфер).
- Точная причина отказа operator new (фрагментация,
  исчерпание адресного пространства, некорректные размеры
  исходной поверхности) — вопрос рантайма; статикой
  не различить.
- Кадры стека ниже sub_1075F80 проходят через трамплины
  patcher_x86 (адреса 0x02CFxxxx) и не смаппены на
  конкретные функции.

Полезность лога для исправления: ВЫСОКАЯ. Дефект
локализован: sub_11B1050 не проверяет результат
конструктора поверхности на NULL, тогда как две
родственные функции такую проверку содержат. Точечная
проверка после call sub_11B6EC0 устраняет краш.

ВЫВОД
-----
Виновник — HD-мод (HD_HOTA.dll, версия 5.7 R33).

Функция сохранения поверхности sub_11B1050 вызывает
конструктор sub_11B6EC0, который при отказе выделения
памяти возвращает NULL. Результат не проверяется,
и последующее чтение поля объекта по смещению 0x1C
от нулевого указателя вызывает исключение доступа.

Дефект конкретный и локализованный: две родственные
функции того же модуля проверяют результат конструктора
на NULL, а падающая функция — нет. Отказ выделения
спровоцирован размером пиксельного буфера (около 4,7 МБ
при разрешении 1486x836 в 32-битном режиме Graphics.Mode=7)
в условиях ограниченного адресного пространства 32-битного
процесса.
