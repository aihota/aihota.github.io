АНАЛИЗ ВЫЛЕТА 0x00600480
=====================================

Модель: Qwen 3.8
Дата: 27.07.2026
Заключение: Разыменование нулевого указателя на back buffer DirectDraw в функции отрисовки кадра A0_Flip_AndDrawCursor_sub_600430. Пропущена проверка глобала A0_DirectDraw_Surface_BackBuffer_dword_6AAD28 перед вызовом vtable.

КРАТКОЕ РЕЗЮМЕ
--------------
Игра падает в главном меню при перерисовке окна (WM_PAINT). Функция
A0_Flip_AndDrawCursor_sub_600430 (WINGRAPH.CPP) проверяет наличие
объекта DirectDraw, но НЕ проверяет наличие поверхности заднего
буфера (back buffer). Когда сообщение WM_PAINT приходит в момент,
когда объект DirectDraw уже создан, а back buffer ещё не создан
(или уже освобождён при смене режима), функция разыменовывает
нулевой указатель и падает. Дефект унаследован от SoD, проявляется
во всех версиях HD-мода (5.7 R3 — R33) и во всех графических
режимах (0/2/4).

6. Механизм сбоя
----------------
Функция A0_Flip_AndDrawCursor_sub_600430 (WINGRAPH.CPP, строка ~52)
выполняет IDirectDrawSurface::GetDC для получения контекста
устройства заднего буфера. Перед вызовом она проверяет:
  1. IsIconic(hWnd) — окно не свёрнуто
  2. A0_DirectDraw_dword_6AAD20 != NULL — объект DirectDraw создан
  3. RECT непустой (right > left, bottom > top)

Но НЕ проверяет A0_DirectDraw_Surface_BackBuffer_dword_6AAD28.

Глобал A0_DirectDraw_Surface_BackBuffer_dword_6AAD28:
  Создание: A0_DirectDrawInit_sub_601AB0, адрес 0x00601C89
    mov A0_DirectDraw_Surface_BackBuffer_dword_6AAD28, eax
    (результат sub_600BB0, IDirectDraw::CreateSurface)
  Уничтожение: A0_DirectDraw_Surfaces_Delete_sub_601E60, адрес 0x00601EDF
    mov A0_DirectDraw_Surface_BackBuffer_dword_6AAD28, esi  (esi=0)
    (после IDirectDrawSurface::Release, vtable +8)

Краш происходит, когда WM_PAINT приходит в окно между:
  а) созданием объекта DirectDraw и созданием back buffer
     (инициализация ещё не завершена);
  б) освобождением back buffer и освобождением объекта DirectDraw
     (смена режима / сворачивание / завершение).

В обоих случаях A0_DirectDraw_dword_6AAD20 != NULL (проверка
проходит), но A0_DirectDraw_Surface_BackBuffer_dword_6AAD28 == NULL
(проверка отсутствует, разыменование NULL).

7. Родственные функции
----------------------
Функция A0_Video_0_API_RestartAndDrawFirstFrame_sub_597C00
(адрес 0x00597EE4) также использует back buffer БЕЗ проверки:
  .text:00597EE4  mov  eax, A0_DirectDraw_Surface_BackBuffer_dword_6AAD28
  .text:00597EF2  mov  edx, [eax]           ; тоже упала бы при EAX=0

Ни одна из функций, использующих back buffer, не проверяет его
на NULL. Единственная проверка — на объект DirectDraw.

11. Воспроизведение вылета
--------------------------
Условие активации: WM_PAINT в момент, когда объект DirectDraw
создан, а back buffer — нет (или уже освобождён).

Базовый сценарий:
  1. Запустить игру (HotA 1.8.0, HD-мод 5.7, любой режим).
  2. Находиться в главном меню.
  3. Спровоцировать перерисовку окна (WM_PAINT) в момент
     инициализации или смены графического режима:
     а) свернуть/развернуть окно (Alt+Tab, Win+D);
     б) изменить разрешение экрана;
     в) переключить полноэкранный/оконный режим.
  4. Если WM_PAINT приходит в окно между созданием DirectDraw
     и созданием back buffer (или между освобождением back buffer
     и освобождением DirectDraw) — вылет.

Варьирование:
  - Graphics.Mode: не влияет (краш в режимах 0/2/4).
  - Разрешение: не влияет (краш при 800x600 — 2560x1440).
  - Версия HD-мода: не влияет (краш в R3 — R33).

Дифф-тест:
  - Без HD-мода (чистый SoD): вылет должен воспроизводиться
    тем же механизмом (код идентичен, но без перехвата
    HD_SCX2.dll). Для подтверждения нужен дамп чистого SoD.

Достоверность и ограничения
----------------------------
Подтверждено:
- Точка сбоя: mov ecx, [eax] при EAX=0 (арифметика: 0+0=0).
- Глобал A0_DirectDraw_Surface_BackBuffer_dword_6AAD28 = NULL:
  единственный writer на создание (0x601C89) и единственный
  на обнуление (0x601EDF) прочитаны в листинге.
- Проверка A0_DirectDraw_dword_6AAD20 присутствует (0x600455),
  проверка back buffer — отсутствует (прочитано, 0x600478-0x600482).
- Родственная функция 0x597EE4 тоже без проверки (прочитано).
- Entry point 0x639C00 = start в листинге.
- 91 вылет, все в главном меню, все HotA 1.8.0.
- Все блоки Comment — автотекст, показаний игроков нет.

Ограничения:
- Точный триггер (какое именно событие Windows создаёт WM_PAINT
  в критическое окно) — runtime-only: нужен отладчик или
  логирование последовательности DirectDraw init/delete.
- Минидампы сокращённые (без кучи): подтверждают CONTEXT/регистры,
  но не дают состояние объектов DirectDraw в момент сбоя.
- Листинг HD_SCX2.dll не верифицирован по версии (периферийный
  модуль): не влияет на диагноз (виновник — h3hota.exe).
- Флаг «Были в SoD» выставлен по структурному анализу кода
  (WINGRAPH.CPP — оригинальный файл SoD); дампов чистого SoD
  для этого адреса нет.

ВЫВОД
-----
Вылет 0x00600480 — разыменование нулевого указателя на поверхность
заднего буфера DirectDraw в функции отрисовки кадра
A0_Flip_AndDrawCursor_sub_600430 (WINGRAPH.CPP, h3hota.exe).
Функция проверяет наличие объекта DirectDraw, но не проверяет
наличие back buffer перед вызовом vtable (IDirectDrawSurface::GetDC).
Когда WM_PAINT приходит в момент неполной инициализации или
частичного освобождения DirectDraw-поверхностей, глобал
A0_DirectDraw_Surface_BackBuffer_dword_6AAD28 равен NULL,
что приводит к падению. Дефект структурный (пропущена одна
проверка), унаследован от SoD, проявляется во всех версиях
HD-мода и графических режимах. Фикс: добавить проверку
if (!A0_DirectDraw_Surface_BackBuffer_dword_6AAD28) return;
перед строкой 0x600478. Код в закрытом бинаре — репорт
разработчикам HotA/HD-мода.
