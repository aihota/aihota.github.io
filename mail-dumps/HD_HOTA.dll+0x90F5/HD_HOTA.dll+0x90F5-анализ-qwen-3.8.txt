============================================================

Модель: Qwen 3.8
Дата: 29.07.2026
Заключение: HD-мод (HD_HOTA.dll) падает при закрытии диалога
выбора карты: хук очистки диалога обходит связный список
элементов и натыкается на узел, который уже освобождён.

КРАТКОЕ РЕЗЮМЕ
--------------
При закрытии диалога выбора карты в сетевой игре HD-мод
выполняет собственную процедуру очистки (sub_1008FB0):
обходит двусвязный список элементов диалога с хвоста
и для каждого узла вызывает штатную функцию отсоединения
A0_Dlg_DetachItem (0x5FF320 в h3hota.exe). Обход падает
на инструкции чтения указателя prev у узла, память под
которым уже освобождена: EAX содержит адрес узла,
чтение [EAX+8] обращается к недоступной странице.
Адрес сбоя каждый раз разный (куча), но регистровый
профиль и стек полностью совпадают во всех трёх дампах.
Баг устойчив: тот же механизм виден в дампах версий
HD-мода R14, R22, R29 на других адресах.

5. Инструкция краша и адресная проверка
----------------------------------------
Листинг HD_HOTA.dll-5.7 R33, функция sub_1008FB0
(хук очистки диалога, замещает штатный путь SoD):

    .text:010090E9  mov  eax, [edi+2Ch]   ; хвост списка
    .text:010090EC  test eax, eax
    .text:010090EE  jz   short loc_1009103
    .text:010090F0  mov  ebx, 5FF320h     ; A0_Dlg_DetachItem
    .text:010090F5 loc_10090F5:           ; цикл обхода
    .text:010090F5  mov  esi, [eax+8]     ; <-- КРАШ: esi = prev
    .text:010090F8  mov  ecx, edi
    .text:010090FA  push eax
    .text:010090FB  call ebx              ; отсоединить узел
    .text:010090FD  mov  eax, esi
    .text:010090FF  test esi, esi
    .text:01009101  jnz  short loc_10090F5 ; следующий узел

Это цикл уничтожения двусвязного списка элементов диалога:
начиная с хвоста ([edi+2Ch]), для каждого узла сохраняется
указатель prev ([eax+8]), затем узел отсоединяется вызовом
A0_Dlg_DetachItem, после чего обход переходит к prev.

Адресная проверка (база + смещение == адрес сбоя):
  Дамп 1: EAX = 0x1B3D6FE8, [EAX+8] = 0x1B3D6FF0 == адрес сбоя
  Дамп 2: EAX = 0x1A997800, [EAX+8] = 0x1A997808 == адрес сбоя
  Дамп 3: EAX = 0x14FAEA48, [EAX+8] = 0x14FAEA50 == адрес сбоя
  Все три совпадают.

Механика отказа. EAX указывает на узел списка, память
под которым уже возвращена системе (страница недоступна).
Чтение [EAX+8] вызывает EXCEPTION_ACCESS_VIOLATION.
Адреса сбоя лежат в диапазоне кучи (0x14..0x1B млн),
каждый раз разные — это не NULL и не отладочный маркер,
а живой указатель на мёртвую память.

A0_Dlg_DetachItem_sub_5FF320 (h3hota.exe) только
отсоединяет узел от списка (правит prev/next у соседей,
обновляет голову [edi+28h] и хвост [edi+2Ch]), но НЕ
освобождает память узла. Значит, узел был освобождён
ДО вызова sub_1008FB0 — кем-то другим.

7. Анализ регистров и группировка
---------------------------------
Группировка: все 3 дампа — один адрес сбоя (HD_HOTA.dll+0x90F5),
одна операция (чтение), один непосредственный вызывающий код
(трамплин 0x0212272C). Группа единая.

Регистры:
  EAX — указатель на текущий узел списка (разный, куча)
  EBX = 0x5FF320 — A0_Dlg_DetachItem (постоянный)
  ECX = EDI = 0x128680 — объект диалога на стеке (постоянный)
  EDX = 0 — не используется в цикле
  ESI — в точке краша хранит прежнее значение (ArgList
    из начала функции): 0x49C (дампы 1, 3) или 0x540 (дамп 2);
    это глобальная переменная, не связана с механизмом сбоя
  ESP/EBP — стековый кадр sub_1008FB0 (постоянный)

Постоянство ECX = EDI = 0x128680 означает, что объект
диалога лежит на стеке вызывающего кода по одному и тому
же адресу во всех трёх вылетах. Это согласуется с тем,
что диалог выбора карты создаётся как локальный объект
в A0_MapSelectDlg_Run.

8. Первопричина
---------------
sub_1008FB0 — хук HD-мода, замещающий штатную очистку
диалога при отсоединении. Он обходит список элементов
диалога ([edi+2Ch] — хвост, [edi+28h] — голова) и для
каждого узла вызывает A0_Dlg_DetachItem.

Штатный путь SoD (loc_1009111 в sub_1008FB0) не обходит
список явно — он делает виртуальный вызов через vtable
аргумента. Обход списка — добавление HD-мода.

Краш происходит потому, что в списке элементов диалога
находится указатель на узел, память под которым уже
освобождена. Обход начинается с хвоста ([edi+2Ch]),
и хвостовой узел (или один из последующих по цепочке
prev) оказывается мёртвым.

Кто освободил узел преждевременно — статически не
установить, но сужено до двух кандидатов.

Кандидат 1 (внешний). Цикл диалога в
A0_WndMgr_Run_MapSelectDlg вызывает
A0_Global_CyclePalettesColors_RefreshTurnTimer_RecieveNetMsgs
(обработка сетевых сообщений и таймеров) и
A0_Dlg_Items_ProcMsg (обработка сообщений элементов).
Любой из этих путей может освободить элемент диалога
при обновлении содержимого (смена списка карт,
обновление слотов игроков), не извлекая его из
связного списка.

Кандидат 2 (внутренний). Штатная функция
A0_Dlg_DeleteItems_sub_5FFAD0 (h3hota.exe) обходит
МАССИВ элементов ([esi+34h]..[esi+38h]) и вызывает
виртуальный деструктор (vtable[0], arg=1) для каждого,
освобождая память. Но она НЕ извлекает элементы из
связного списка ([+28h]/[+2Ch]). Если
A0_Dlg_DeleteItems вызывается до хука sub_1008FB0
(например, через виртуальный вызов [vtable+8] в
A0_WndMgr_Dlg_Detach), связный список остаётся
с мёртвыми указателями.

Дополнительный фактор: краш происходит в SEH-
обработчике (адрес возврата 0x602F9F, а не 0x602F28
нормального выхода). Первое исключение в цикле диалога
было поймано SEH, и обработчик попытался очистить
диалог. Очистка упала на том же битом списке. Это
означает, что порча списка произошла ДО первого
исключения, и оба сбоя (первое исключение и краш
в SEH-обработчике) имеют общий корень.

Семейство. Тот же механизм (чтение [EAX+8] при обходе
списка элементов, EBX = 0x5FF320, EDI = 0x128680)
наблюдается в дампах других версий HD-мода:
  HD 5.7 R14: HD_HOTA.dll+0x8E15 (игрок nitro)
  HD 5.7 R22: HD_HOTA.dll+0x8E25 (игрок artyomsarazov)
  HD 5.7 R29: HD_HOTA.dll+0x9065 (игрок dmitrygrebenkin)
Адреса различаются из-за перекомпоновки кода между
версиями, но регистровый профиль и стек идентичны.
Баг не исправлен как минимум с R14 по R33.

11. Воспроизведение вылета
--------------------------
Условие активации: сетевая игра, диалог выбора карты
закрывается (отсоединяется от менеджера окон).

Базовый сценарий:
  1) Запустить игру под Wine 8.0.1 (или Windows).
  2) Создать сетевую партию, открыть лобби.
  3) Выбрать карту [HotA] Air Supremacy.h3m.
  4) Начать игру, дойти до дня 1 недели 11.
  5) Выполнить действие, вызывающее закрытие диалога
     выбора карты (переход из лобби в игру, смена
     карты, возврат в лобби).

Варьирование:
  Графический режим: Graphics.Mode = 5 (32 бита,
    stretchable). Все 3 дампа в этом режиме, но
    sub_1008FB0 не ветвится по Graphics.Mode —
    режим не влияет на механизм.
  Версия HD-мода: баг виден с R14 по R33, версия
    не критична.

Дифф-тест:
  Штатный путь SoD (без хука HD-мода) не обходит
  список элементов при отсоединении диалога.
  Отключение хука sub_1008FB0 (замена на штатный
  виртуальный вызов) исключает этот краш, но может
  нарушить расширенную очистку HD-мода.

ДОСТОВЕРНОСТЬ И ОГРАНИЧЕНИЯ
----------------------------
Подтверждено:
- Адресная арифметика: EAX + 8 == адрес сбоя во всех
  3 дампах.
- Инструкция краша: mov esi, [eax+8] в sub_1008FB0,
  цикл обхода списка элементов диалога.
- Версия листинга: entry point 0x11C4547 совпадает,
  функции стека разрешаются в осмысленные имена.
- Семейство: тот же механизм в R14, R22, R29 (4 адреса,
  9 дампов суммарно).
- Штатный путь SoD не обходит список явно (loc_1009111
  делает виртуальный вызов, обход — добавление HD-мода).
- Краш в SEH-обработчике: адрес возврата 0x602F9F
  (исключение в цикле диалога), а не 0x602F28
  (нормальный выход).
- A0_Dlg_DeleteItems_sub_5FFAD0 освобождает элементы
  через массив [+34h]/[+38h], не извлекая из связного
  списка [+28h]/[+2Ch] — доказанный рассинхрон двух
  коллекций диалога.

Ограничения:
- Минидампы сокращённые (без кучи): содержимое узла
  по EAX не прочесть, невозможно установить, когда
  и кем узел был освобождён.
- Точный код-путь, освободивший узел преждевременно,
  статически не установлен: два кандидата (внешний —
  обработка сетевых сообщений в цикле диалога;
  внутренний — A0_Dlg_DeleteItems через виртуальный
  вызов [vtable+8] в A0_WndMgr_Dlg_Detach).
- Показания игроков отсутствуют.
- Все дампы из одной сетевой партии (одна карта, один
  день) — не исключено, что триггер специфичен для
  этой карты или этого состояния игры.

ВЫВОД
-----
HD-мод (HD_HOTA.dll) падает при очистке диалога выбора
карты в сетевой игре. Краш происходит в SEH-обработчике:
сначала исключение в цикле диалога ловится SEH, затем
обработчик пытается отсоединить диалог, и хук очистки
sub_1008FB0 падает на обходе связного списка элементов.
Хвостовой узел списка указывает на освобождённую память:
чтение указателя prev ([EAX+8]) обращается к недоступной
странице.

Механизм доказан (адресная арифметика, инструкция краша,
цикл обхода списка, SEH-путь по адресу возврата).
Корневая причина — рассинхрон двух коллекций диалога:
штатная A0_Dlg_DeleteItems освобождает элементы через
массив [+34h]/[+38h], не извлекая из связного списка
[+28h]/[+2Ch]. Точный код-путь, освободивший узел,
требует рантайм-верификации (полный минидамп с кучей,
точки останова на выделении/освобождении элементов).

Баг устойчив: наблюдается с версии HD-мода 5.7 R14
по R33 на четырёх разных адресах (9 дампов). Штатный
путь SoD не обходит список элементов при отсоединении
диалога — обход является добавлением HD-мода, и дефект
связан именно с этим добавлением.
