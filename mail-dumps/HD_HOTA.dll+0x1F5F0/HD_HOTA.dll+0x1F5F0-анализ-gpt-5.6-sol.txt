АНАЛИЗ ВЫЛЕТА  HD_HOTA.dll+0x1F5F0  (инициализация slider-ресурсов HiRezCore)
================================================================================

    Модель: GPT-5.6 Sol
    Дата:   31.08.2026
    Заключение: два возврата GetBitmap816 не проверены; NULL от slider.pcx прочитан через [EDI+0x28].

КРАТКОЕ РЕЗЮМЕ
--------------

Что произошло:

    HD-мод 5.8 R6 при построении интерфейса карты запросил slider.pcx и
    sliderV.pcx. Оба запроса вернули NULL, после чего HD_HOTA.dll упал.

Локальный механизм:

    EDI=0 сохранён в ExceptionStream. Инструкция push dword ptr [edi+28h]
    вычисляет адрес 0x00000028, точно совпадающий с адресом чтения в журнале.

Охват семейства:

    Точный адрес +0x1F5F0 найден один раз среди 5492 разобранных журналов.
    Первичный лог 5.7 R20 с +0x1E206 и точный листинг подтверждают тот же
    механизм: два запроса slider-ресурсов и чтение NULL+0x28. В семье 2 события;
    полнота переписи остаётся частичной.

Граница доказанности:

    Доказан пропущенный контроль двух результатов, допускающих NULL. Причина
    двух возвратов NULL не установлена. Метаданные ExceptionStream называют
    поток 16000, но ESP/EBP контекста лежат в диапазоне стека главного потока
    16132; стек потока 16000 с регистрами не объединялся.

3. Точка сбоя
-------------

Локальная арифметика:

- Инструкция читает DWORD по адресу EDI+0x28. EDI=0 непосредственно в
  ExceptionStream, поэтому эффективный адрес равен 0x00000028 и совпадает с логом.
- EBX=0x0055AA10 соответствует ResourceManager::GetBitmap816(const char *).
  Возврат первого вызова скопирован в EDI; возврат второго остался в EAX.
  EDI=0 и EAX=0 показывают два последовательных неуспешных получения bitmap.
- Второй NULL также опасен: по 0x0101F5F9 EAX копируется в EBX, а по
  0x0101F60E следует mov edx,[ebx+24h]. До него выполнение не дошло только
  потому, что первый NULL раньше вызвал исключение на [edi+28h].
- Смещение +0x28 относится к полю объекта Bitmap816; точное имя поля для вывода
  о NULL не требуется. Негоден сам базовый указатель, а не значение поля.
- Контекст внутренне согласован с кадром: ESI=0 соответствует xor esi,esi, а
  EBP-0x60-0x0C = 0x0019FD54, то есть фактическому ESP после трёх push.
- ESP/EBP лежат в диапазоне стека потока 16132. Стек потока 16000, указанного
  в метаданных ExceptionStream, с этим набором регистров не объединялся.

4. Цепочка вызовов и контекст
-----------------------------

    -> sub_10206F0: ветвь включённого компонента "HD.UI.HiRezCore"
    -> sub_101F5C0: построение/масштабирование UI-ресурсов карты приключений
    -> GetBitmap816("slider.pcx") -> NULL, сохранение в EDI
    -> GetBitmap816("sliderV.pcx") -> NULL
    -> sub_101F5C0: push dword ptr [EDI+0x28] — ВЫЛЕТ

- Полный механический перебор листинга нашёл одну разрешённую вызывающую функцию
  для sub_101F5C0: вызов 0x01020841 из sub_10206F0. Возврат 0x08830846 в V2
  соответствует следующей инструкции 0x01020846 и подтверждает этот кадр.
- Заголовок журнала и диапазон ESP/EBP связывают текстовый Context и V2 со
  стеком главного потока 16132. ExceptionStream указывает номер потока 16000; статус
  CONTEXT_THREAD_MISMATCH сохранён как ограничение входа.
- Внешний кадр 0x02A929DB оставлен вне доказательной цепочки: его модуль и
  происхождение не разрешены статически; стек потока 16000 не привлекался.

5. Первопричина
---------------

Доказанный локальный дефект:

- HD_HOTA.dll использует допускающий NULL результат GetBitmap816 без проверки. В других
  потребителях того же адреса есть явные test reg,reg и переходы при NULL
  (0x011B3474, 0x011B4E55, 0x011B544D, 0x011B592D, 0x011B67C3, 0x011B69FE).

Рабочая гипотеза:

- Общий отказ загрузки PCX затронул slider.pcx и sliderV.pcx. GetBitmap816 ищет
  кеш, отдельный файл и подключённые LOD, затем может использовать default.pcx;
  NULL возможен при недоступном резерве или отказе создания объекта. Какой путь
  сработал здесь, MiniDumpNormal не показывает; утверждение о нехватке памяти недоказано.

Исправление на стороне HD-мода:

- Проверяемые ресурсы — EDI для slider.pcx и EAX для sliderV.pcx. Второй
  результат затем попадает в EBX и без проверки читается через [EBX+0x24].
- Сразу после второго вызова проверить EDI и EAX; если любой равен NULL, перейти
  в общий путь отказа до чтений [EDI+0x28] и [EBX+0x24].
- При NULL не вызывать дальнейшую сборку и вернуть управление из sub_101F5C0.
  Проверку провести до временных изменений; нулевой путь должен восстановить состояние
  и освободить уже полученный парный ресурс.
- Перед патчем нужна проверка сигнатуры и байтов около 0x0101F5F0.
- До исправления вызов с NULL приводит к вылету; после исправления функция возвращает
  управление через путь отказа без обращения к 0x00000028.
- В 5.8 R8 участок совпадает с R6 (944 инструкции, 126 вызовов), поэтому проверку
  требуется внести как минимум в общую реализацию этих сборок.

Дифференциальный тест:

- На копии установки принудительно вернуть NULL отдельно для slider.pcx,
  sliderV.pcx и обоих ресурсов. Старая сборка достигает +0x1F5F0; исправленная
  не читает 0x28 и фиксирует точный отказ поставщика.

1. Запустить чистую HotA 1.8.1 + HD-мод 5.8 R6 с активным HiRezCore, включить
   журналирование GetBitmap816 и открыть карту приключений, инициируя сборку UI.

1. В тестовой копии инъекцией заставить поставщика вернуть NULL для одного и двух

Ожидаемый результат исправленной сборки:

- Ни один NULL не разыменовывается; UI либо использует валидный резервный ресурс, либо
  выдаёт конкретную ошибку ресурса и контролируемо прекращает инициализацию.

Необходимая телеметрия:

- Имена ресурсов, выбранная ветвь кеш/файл/LOD/default, причина отказа создания,
  результаты обоих вызовов, список подключённых LOD и полный дамп потока исключения.

8. Достоверность и ограничения
------------------------------

Подтверждено:

- EIP, EDI=0, EAX=0, адрес чтения и точная инструкция; внутренняя арифметика
  кадра; единственная статически разрешённая вызывающая функция R6; поставщик
  0x0055AA10 и наличие защищённых родственных потребителей.
- Та же последовательность slider.pcx/sliderV.pcx и чтение NULL+0x28 подтверждены
  первичным журналом и точным листингом 5.7 R20. Код R6 также совпадает с R8.

Отрицательные результаты:

- В совокупности 5492 разобранных журналов после дедупликации фильтр поля
  Address дал по одному событию для +0x1F5F0 и +0x1E206; обход полный,
  0 усечённых и 0 нечитаемых журналов.
- Журнал указывает активный каталог Compability/#hota15. В локальном снимке он
  содержит DEF, BMP и INI, но не LOD; отдельных slider.pcx/sliderV.pcx в 181 нет.
- Ресурсы не найдены и в контрольных H3bitmap.lod, HotA.lod и #sod_ru/h3ab_bmp.lod.
  Эти архивы не являются активным #hota15 и не доказывают состояние установки игрока.

Статическое исчерпание:

- Инструкция, вызывающая функция, поставщик, запись EAX->EDI, тип Bitmap816 и условие HiRezCore
  проверены. Безопасная родственная функция sub_101F510 и шесть потребителей с проверками найдены.
- Глобальный знаменатель потребителей не заявляется: 140 текстовых ссылок на
  0x0055AA10 включают косвенные вызовы через регистр, не разрешаемые штатной переписью.
- Аллокаций до точки сбоя внутри sub_101F5C0 нет. Ветка выделения внутри поставщика
  известна статически, но состояние кучи во время выполнения не захвачено.

Матрица уверенности:

- Точка сбоя: подтверждена
- Локальный механизм: подтверждён
- Происхождение состояния: не установлено
- Охват семейства: частичный
- Уровень причинности: L1

Ограничения:

- MiniDumpNormal не содержит Memory64List, состояния кеша/LOD и достаточной кучи.
- Причина двух NULL, точная конфигурация ресурсов игрока и пользовательский
  триггер не установлены. Дамп не содержит хэш h3hota HD.exe. Локальный
  одноимённый файл совпадает с журналом по размеру образа 0x2E7000 и точке
  входа 0x00639C00.
- CONTEXT_THREAD_MISMATCH: ExceptionStream называет номер потока 16000, тогда как ESP/EBP
  контекста лежат в стеке номер потока 16132. Контекст согласуется с главным потоком,
  но стек 16000 и неразрешённые внешние кадры в доказательную цепочку не включены.

ВЫВОД
-----

Контрольный расчёт:

    базовое значение = EDI = 0x00000000
    смещение поля = 0x28
    эффективный адрес = 0x00000000 + 0x28 = 0x00000028
    инструкция = push dword ptr [edi+28h]

Происхождение состояния:

    NULL пришёл из GetBitmap816("slider.pcx"); конкретная причина возврата NULL
    не установлена. Второй независимый запрос sliderV.pcx также вернул NULL.

Действия:

Адресат: разработчик HD-мода (компонент HiRezCore).

- Добавить проверки обоих возвратов в sub_101F5C0 до 0x0101F5F0 и безопасную
  очистку/резервный ресурс с журналированием причины отказа поставщика.
- Повторить тесты без NULL, с одним NULL и с двумя NULL; проверить отсутствие чтения 0x00000028.

Критерий завершения:

    Исправленная сборка не разыменовывает NULL при любом отказе slider-ресурсов,
    а телеметрия отдельно устанавливает первопричину отказа GetBitmap816.
