================================================================
АНАЛИЗ ВЫЛЕТА HD_HOTA.dll+0x1A49
================================================================

Модель: Qwen 3.8
Дата: 20.08.2026
Заключение: HD_HOTA.dll вызывает int 3 после возврата NULL из _malloc.
Непосредственный механизм подтверждён, а причина отказа памяти не установлена.

КРАТКОЕ РЕЗЮМЕ
--------------
Что произошло:

    Во всех пяти уникальных DMP точка сбоя совпадает с
    HD_HOTA.dll+0x1A49. Исключение имеет тип EXCEPTION_BREAKPOINT.

Локальный механизм:

    В листинге R35 по этому смещению находится int 3. Перед ловушкой
    функция проверяет результат _malloc; при EAX = 0 ветка завершается сбоем.

Охват семейства:

    Два из семи TXT содержат повторные двоичные состояния DMP. Локальный
    счёт равен пяти уникальным DMP, а реестр содержит семь TXT-инцидентов.

Граница доказанности:

    Причина возврата NULL по сокращённым DMP не установлена. Возможны
    давление на адресное пространство и повреждение кучи.

Для обоих DMP нормализация адреса даёт 0x01001A49. Листинг R35

3. Точка сбоя
-------------
Формула нормализации:

    адрес IDA = EIP - база загрузки + база образа

Для DMP 1:

    0x04A91A49 - 0x04A90000 + 0x01000000 = 0x01001A49

Для DMP 2:

    0x04421A49 - 0x04420000 + 0x01000000 = 0x01001A49

Листинг R35:

    .text:01001A45  test eax, eax
    .text:01001A47  jnz  short loc_1001A4B
    .text:01001A49  int  3
    .text:01001A4A  retn

Адрес попадает на границу однобайтовой инструкции int 3.

4. Цепочка вызовов и контекст
-----------------------------
По листингу и контексту DMP локальная цепочка выглядит так:

    парсер строковых тегов
    -> sub_1001C70
    -> sub_1001A30, отладочный распределитель памяти
    -> _malloc, возврат NULL
    -> проверка EAX
    -> int 3 по адресу 0x01001A49  <-- СБОЙ

Трамплины patcher_x86 затрудняют полное восстановление внешних
кадров. Для вывода о локальном механизме внешняя часть стека не
нужна: проверка EAX и ловушка находятся в одной функции.

5. Первопричина
---------------
Локальный механизм подтверждён: int 3 выполняется после возврата
NULL из _malloc. Это объясняет EXCEPTION_BREAKPOINT и EAX = 0.

Причина возврата NULL по сокращённым DMP не установлена. Для R40
рабочей гипотезой остаётся давление на 32-битное адресное
пространство. Для R35 также нельзя исключить повреждение кучи.
Полного снимка памяти для проверки этих вариантов нет.

Исправление на стороне HD-мода:

1. Проверять указатель нового буфера на NULL до первого доступа и до
   временной записи состояния.
2. При NULL немедленно завершать ветку: не вызывать int 3, вернуть явную
   ошибку и сохранить старый объект без частичных изменений.
3. Сначала выделить и проверить новый блок, затем скопировать данные.
4. Только после успеха заменить указатель, размер и ёмкость, затем освободить
   старый блок.
5. Перед патчем сверить точную сигнатуру, байтовую последовательность и хеш
   листинга; при несовпадении сигнатуры патч не применять.

Дифференциальный тест:
- До исправления внедрённый отказ вызывает вылет.
- После исправления тот же отказ возвращает явную ошибку без ловушки,
  завершает функцию без вылета и сохраняет старое состояние.
