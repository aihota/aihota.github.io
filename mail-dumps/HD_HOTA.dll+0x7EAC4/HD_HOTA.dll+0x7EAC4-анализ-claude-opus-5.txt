АНАЛИЗ ВЫЛЕТА  HD_HOTA.dll+0x7EAC4  (запуск HD-мода)
================================================================================

    Модель: Notion AI
    Дата:   13.08.2026
    Заключение: дефект самого HD-мода: в процедуре HD_HOTA.dll+0x7D740
    результат инициализации сохраняется в глобальную переменную
    dword_1215884 без проверки на ноль и через 0x3D8 байт разыменовывается
    в той же процедуре, что даёт чтение по адресу 0x00000000 при запуске

КРАТКОЕ РЕЗЮМЕ
--------------

    Игра упала на запуске, до входа в партию: внутриигровые поля лога
    нулевые (Me: 0, Active Player: 0, Game Type = 0, Network Game = 0,
    Last RMG Seed = 0), полей Day и Map file в логе нет. Экспорт Start
    модуля HD_HOTA.dll (HD_HOTA.dll+0x96FB0) поднимает подсистемы мода
    одну за другой; одним из шагов он вызывает процедуру
    HD_HOTA.dll+0x7D740, и падение происходит внутри неё.

    Процедура сначала создаёт объект: результат косвенного вызова кладётся
    в глобальную переменную dword_1215884 по адресу HD_HOTA.dll+0x7E6EC.
    Проверки результата на ноль там нет. Ровно через 0x3D8 байт, в той же
    процедуре, этот глобал читается обратно и разыменовывается: сначала
    берётся указатель на таблицу методов, затем метод [+24h], затем
    вызов. В момент падения EAX равен нулю, поэтому чтение уходит по
    адресу 0x00000000.

    Имя dword_1215884 встречается в листинге 5.7 R40 28 раз: 26 чтений,
    1 запись и 1 объявление в .data (28 = 26 + 1 + 1, основание - все
    строки листинга с этим именем). Проверку на ноль перед
    разыменованием ищет автоматический поиск test/cmp/условный переход
    в окне после чтения, и ширина окна входит в число: при окне 3
    инструкции проверок нет ни у одного из 26 чтений, при окне 6 они
    есть у 3 чтений, при окне 12 - у 6. Контроль метода на том же входе:
    тот же поиск находит 4214 инструкций test eax, eax в этом листинге,
    то есть шаблон рабочий.

    Тот же механизм виден на соседней сборке 5.7 R36 по адресу
    HD_HOTA.dll+0x7E624: там та же по строению процедура
    HD_HOTA.dll+0x7D2D0, тот же фрагмент записи глобала и та же
    дистанция 0x3D8 байт от записи до разыменования. Между R36 и R40
    сместились адреса и имена, конструкция осталась прежней.

2. Проверка листинга и адреса
-----------------------------

    Адресная арифметика. В логе модуль HD_HOTA.dll загружен по адресу
    0x02FE0000, размер образа 0x011F9000, адрес вылета 0x0305EAC4.
    Смещение в модуле равно 0x0305EAC4 - 0x02FE0000 = 0x7EAC4 и совпадает
    с заголовком лога Address: [HD_HOTA.dll+0x7EAC4]. Листинг собран с
    imagebase 0x01000000, поэтому адрес в листинге равен
    0x01000000 + 0x7EAC4 = 0x0107EAC4.

    Попадание в листинг. Адрес 0x0107EAC4 найден в файле
    modules/HD_HOTA.dll-5.7 R40.txt в строке 212866 и лежит внутри
    процедуры sub_107D740 (начало в строке 210933, адрес 0x0107D740, то
    есть HD_HOTA.dll+0x7D740), смещение от начала процедуры 0x1384.
    Версия листинга и версия из лога совпадают: 5.7 R40.

    Строка листинга по адресу вылета:

    .text:0107EAC4                 mov     eax, [eax]

    Карта покрытия листингами - что из участников этого вылета можно
    было проверить статически:

    Модуль         Версия     Листинг   Что проверено
    ---------------------------------------------------------------------
    HD_HOTA.dll    5.7 R40    есть     адрес вылета, процедура, глобал
    HD_HOTA.dll    5.7 R36    есть     родственный вылет +0x7E624
    HD_HOTA.dll    5.7 R31    есть     та же конструкция раньше
    HotA.dll       1.8.0      есть     в цепочке не участвует
    h3hota.exe     -          есть     адрес 0x004C6CA0, к цепочке не относится
    _HD3_.dll      7 версий   есть     в цепочке не участвует
    остальные     из дампа   часть     не проверялись

    Всего в папке modules 80 листингов, из них HD_HOTA.dll - 30 версий,
    HotA.dll - 10 версий, остальное - игровой исполняемый файл и
    вспомогательные библиотеки.


3. Точка сбоя
-------------

    Падающая инструкция читает четыре байта по адресу из EAX,
    а в EAX непосредственно перед этим загружается значение глобальной
    переменной dword_1215884. Значит, в момент вылета глобал был
    равен нулю.

    .text:0107EABA                 mov     eax, dword_1215884
    .text:0107EABF                 mov     ecx, offset unk_11FC17C
    .text:0107EAC4                 mov     eax, [eax]
    .text:0107EAC6                 mov     eax, [eax+24h]
    .text:0107EAC9                 call    eax

    Это обычный вызов виртуального метода: первая инструкция берёт
    указатель на таблицу методов объекта, вторая берёт из таблицы
    метод с номером 9 (смещение [+24h], то есть 36 байт, делённые на
    4), третья вызывает его. При нулевом объекте невыполним уже первый
    шаг, поэтому система даёт 0xC0000005 на чтение по адресу 0x00000000.

    Регистры в момент исключения: EAX 0x00000000, ECX 0x031DC17C,
    EDX 0x000003E6, EBX 0x025E6208, ESP 0x0012FC20, EBP 0x0012FE58,
    ESI 0x002E26C8, EDI 0x002E26C8. Они подтверждают адрес остановки:
    ECX уже содержит константу из предыдущей инструкции
    (unk_11FC17C при загрузке модуля по 0x02FE0000 даёт ровно
    0x031DC17C), а EAX уже обнулён чтением глобала. Значит, выполнены
    обе инструкции до 0x0107EAC4, и исключение случилось ровно на ней,
    а не раньше.


4. Цепочка вызовов и контекст
-----------------------------

    Экспорт Start модуля HD_HOTA.dll занимает в листинге адреса
    0x01096FB0 - 0x010970B8. По адресу 0x010970A5 он делает вызов, который
    приводит в процедуру HD_HOTA.dll+0x7D740; адрес возврата -
    0x010970AA, то есть хвост того же Start. Сам вылет происходит внутри
    вызванной процедуры, на смещении 0x1384 от её начала.

    -> h3hota.exe: старт игры и загрузка HD_HOTA.dll
    -> HD_HOTA.dll+0x96FB0, экспорт Start: подъём подсистем мода
    -> HD_HOTA.dll+0x7D740: создание объекта и запись результата
       в dword_1215884 по адресу HD_HOTA.dll+0x7E6EC
    -> HD_HOTA.dll+0x7EABA: обратное чтение того же глобала
    -> HD_HOTA.dll+0x7EAC4: разыменование нуля, ВЫЛЕТ

    Стек в логе не размотан по именам функций, поэтому цепочка выше
    восстановлена по листингу: по перекрёстным ссылкам на процедуру и по
    адресу возврата, а не по кадрам стека из дампа.

    Участок от начала блока до падения линейный: между 0x0107EA46 и
    0x0107EAC4 (126 байт) нет ни одного условного перехода, который мог
    бы обойти разыменование. Если исполнение дошло до 0x0107EA46, при
    нулевом глобале падение неизбежно.


5. Первопричина
---------------

    Ноль в глобале появляется в той же процедуре. За 0x3D8 байт до места
    падения, по адресу HD_HOTA.dll+0x7E6EC (строка листинга 212429),
    результат косвенного вызова сохраняется в dword_1215884 и сразу
    сбрасывается сопутствующий флаг:

    .text:0107E6EA                 call    eax
    .text:0107E6EC                 mov     dword_1215884, eax
    .text:0107E6F1                 mov     byte_1211548, 0

    Между вызовом и сохранением нет ни проверки EAX на ноль, ни ветки
    на случай неудачи. Если вызванная функция вернула ноль - не создала
    объект, не нашла ресурс или отказалась работать в этой обстановке -
    ноль просто становится значением глобала, и подсистема считается
    поднятой.

    Ответственность делится на два условия, и нужны оба:

    - писатель по адресу HD_HOTA.dll+0x7E6EC принимает результат
      косвенного вызова без проверки на ноль и публикует его как
      готовый объект;

    - потребитель по адресу HD_HOTA.dll+0x7EAC4 разыменовывает
      опубликованное значение, тоже без проверки на ноль.

    Первое условие делает ноль возможным, второе превращает его в вылет.
    По отдельности ни одно из них к падению не ведёт: при ненулевом
    результате вызова путь проходит нормально, а при проверке у
    потребителя вылета не было бы даже с нулём.

    Насколько беспроверочная работа с этим глобалом типична для модуля,
    показывает автоматический подсчёт по листингу 5.7 R40: из 26 чтений
    dword_1215884 в окне 3 инструкции после чтения проверок на ноль нет
    ни у одного, в окне 6 инструкций проверки есть у 3 чтений (23 из 26
    без проверки), в окне 12 - у 6 чтений (20 из 26 без проверки).
    Ширина окна входит в число: чем шире окно, тем больше посторонних
    проверок в него попадает, поэтому цифру без указания окна
    приводить нельзя. Контроль метода: тот же поиск на том же файле
    находит 4214 инструкций test eax, eax, то есть шаблон видит
    проверки там, где они есть. У чтения по адресу 0x0107EABA проверки
    нет ни при каком окне: сразу за ним идут загрузка константы,
    разыменование и вызов метода.


6. Условия сбоя
---------------

    Чтобы вылет случился, должны совпасть три вещи.

    - Исполнение доходит до подъёма этой подсистемы в экспорте Start,
      то есть до выхода в главное меню. Лог это подтверждает: игровые
      поля пустые, партия не начата.

    - Косвенный вызов по адресу 0x0107E6EA возвращает ноль. Что именно
      он делает, из листинга не видно: адрес функции берётся из памяти
      и статически не разрешается.

    - Управление доходит до линейного участка 0x0107EA46 - 0x0107EAC4,
      где обойти разыменование уже нечем.

    Обстановка этого запуска, которая может влиять на второе условие:
    сборка gog.com SoD, каталог совместимости #hota15 при установленной
    HotA 1.8.0, Windows 7 6.1.7601, Memory.Mod = 0, Graphics.Mode = 5,
    один графический поток. Связь ни одной из этих настроек с нулевым
    результатом вызова листингом не доказана - это перечень условий
    запуска, а не список причин.


7. Воспроизведение вылета
-------------------------

    Управляемого повтора нет: в корпусе mail-dumps адрес
    HD_HOTA.dll+0x7EAC4 встречается один раз - это разбираемый лог,
    второго такого же случая нет. Значит, шагов, которые гарантированно
    приводят к вылету, из логов не извлечь.

    Проверка сама по себе дешёвая: вылет случается на запуске, до
    главного меню, поэтому достаточно повторить ту же связку (HD-мод
    5.7 R40, HotA 1.8.0, gog.com SoD, каталог совместимости #hota15,
    Windows 7) и посмотреть, повторится ли падение по тому же адресу.

    Дифференциальная проверка - что именно подтвердит или опровергнет
    вывод:

    - Тот же запуск, но с каталогом совместимости под установленную
      версию HotA вместо #hota15. Если падение исчезает, значит ноль
      возвращает шаг, зависящий от каталога совместимости.

    - Тот же набор на HD-моде 5.7 R36. Там та же конструкция лежит по
      адресу HD_HOTA.dll+0x7E624, и падение должно повториться именно
      там; если на R36 не падает, различие между сборками сузит место
      поиска.

    - Отладчик с точкой останова на 0x0107E6EC, то есть на записи
      глобала: значение EAX в этот момент прямо покажет, вернул ли
      создающий вызов ноль. Это отличает случай, когда объект вовсе
      не создан, от случая, когда глобал затёрт позже.


8. Достоверность и ограничения
------------------------------

Подтверждено:

- Адрес вылета ложится на листинг той же версии: 0x0305EAC4 минус
  база 0x02FE0000 даёт смещение 0x7EAC4, в листинге 5.7 R40 это
  адрес 0x0107EAC4, строка 212866, инструкция mov eax, [eax].

- Падающая инструкция разыменовывает значение, только что
  прочитанное из dword_1215884 по адресу 0x0107EABA, а в контексте
  исключения EAX равен нулю, а код исключения 0xC0000005 указан на
  чтение по адресу 0x00000000.

- Запись в тот же глобал без проверки на ноль найдена в той же
  процедуре по адресу 0x0107E6EC, строка 212429; расстояние от записи
  до места падения 0x3D8 байт.

- Место в цепочке подтверждено вызовом из экспорта Start: вызов по
  адресу 0x010970A5 внутри участка 0x01096FB0 - 0x010970B8.

- Та же конструкция есть в соседней версии 5.7 R36: процедура
  HD_HOTA.dll+0x7D2D0, глобал dword_1215880, запись по 0x0107E24C,
  родственный вылет по +0x7E624 с той же дистанцией 0x3D8 байт.

Ограничения:

- Что именно возвращает косвенный вызов по 0x0107E6EA, статически не
  определяется: адрес функции берётся из памяти во время работы.
  Поэтому причина появления нуля названа классом (создание объекта
  не удалось), а не конкретной функцией.

- Значение глобала в момент падения из дампа не подтверждено: дамп
  малый, в нём 19 областей памяти общим объёмом 24.0 КБ, и
  рантайм-адрес глобала 0x031F5884 ни в одну из них не попал.
  Нулевое значение выведено из регистра EAX и из инструкции чтения,
  а не из содержимого памяти.

- Стек в логе не размотан, кадры вызовов не восстановлены:
  приведённая цепочка собрана по листингу, а не по дампу.

- Вылет не воспроизводился на стенде и не повторялся управляемо:
  второго лога с этим адресом в корпусе нет.

- Модули из дампа на посторонние вмешательства не разбирались
  поимённо: из 17 модулей листинги есть не для всех, и чужие
  перехваты в этом разборе не проверялись.

Отрицательные результаты:

- Второго лога с этим адресом в корпусе нет. Основание счёта: во всех
  папках mail-dumps 3547 файлов .txt, заголовок вылета есть в 1656 из
  них (в 201 файле он написан с одной буквой d, то есть Adress:),
  различных адресов 335. Шаблон HD_HOTA.dll+0x7EAC4 даёт ровно 1
  попадание - разбираемый лог.

- Соседние адреса того же участка кода в корпусе почти не
  встречаются: по шаблону HD_HOTA.dll+0x7D, +0x7E и +0x7F найдено 4
  лога - наш +0x7EAC4, родственный +0x7E624 и два лога +0x7F84 на
  HD-моде 5.5 R78. Серия не массовая.

- Внутри папки mail-dumps/HD_HOTA.dll: 1393 файла .txt, заголовок вылета
  есть в 1392, различных адресов 320; повторов нашего адреса среди
  них нет.

- Побайтовых копий приложенного дампа в корпусе нет: среди 756
  файлов .dmp ни один, кроме самого файла, не совпал по размеру
  62260 байт. Контроль метода: тем же способом в корпусе находится
  настоящая пара дублей.

    Виноват сам HD-мод: HD_HOTA.dll версии 5.7 R40. В процедуре
    HD_HOTA.dll+0x7D740 результат создающего косвенного вызова
    сохраняется в глобальную переменную dword_1215884 по адресу
    HD_HOTA.dll+0x7E6EC без проверки на ноль, а через 0x3D8 байт та же
    процедура читает этот глобал по адресу HD_HOTA.dll+0x7EABA и
    разыменовывает его по HD_HOTA.dll+0x7EAC4, чтобы вызвать метод
    [+24h]. Если создание объекта не удалось, в глобале лежит ноль,
    и вылет неизбежен: система даёт 0xC0000005 на чтение по адресу
    0x00000000.

    Доказано листингом той же версии: адрес вылета сошёлся по
    арифметике базы (строка 212866), запись и чтение глобала лежат
    в одной процедуре (строки 212429 и 212866), участок перед падением
    линейный. Автору мода: дешевле всего добавить проверку
    результата на ноль сразу после вызова по 0x0107E6EA, до записи
    в dword_1215884. Пока результат принимается без проверки, ноль
    расходится по всем 26 чтениям этой переменной, а не только по
    падающему.

    Осталось непроверенным: какая именно функция вернула ноль (адрес
    вызова берётся из памяти), значение глобала в дампе (нужная
