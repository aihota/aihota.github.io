================================================================
АНАЛИЗ ВЫЛЕТА HD_HOTA.dll+0x1BD83 (отрисовка миникарты)
================================================================

Модель: Qwen 3.8
Дата: 29.07.2026
Заключение: HD-мод воспроизводит логику миникарты SoD
(A0_AdvMgr_Draw_Minimap): case 98 использует значение
A0_MapCell_GetSetup как индекс массива городов без проверки
типа объекта клетки — при герое или корабле индекс выходит
за границы массива. Дефект унаследован из движка SoD.

КРАТКОЕ РЕЗЮМЕ
--------------
HD-мод замещает функцию отрисовки миникарты SoD
(A0_AdvMgr_Draw_Minimap_sub_412BA0) собственной версией
(sub_101AE10). Для case 98 таблицы переходов код получает
foreground-клетку и читает её «setup»-значение функцией
A0_MapCell_GetSetup. Это значение используется как индекс
в массиве городов (поле game_state+0x21614, шаг элемента
0x168 = 360 байт), а прочитанный байт — как индекс цвета
в 16-битной палитре (A0_GamePal_16, 0x6AAD18).

Оригинальный код SoD по адресу 0x412F7D делает ровно то же
самое, без проверки границ. HD-мод воспроизводит логику
движка, включая дефект.

GetSetup возвращает индекс города только для клетки
с городом; для клетки с героем (тип 34) возвращается
значение miu_setup героя, для корабля (тип 8) — индекс
корабля. Эти значения не имеют
отношения к массиву городов и многократно превышают его
размер (наблюдаемые индексы: 91, 141, 167 при типичном
числе городов на карте до 48).

Три дампа на трёх версиях HD-мода (R23, R29, R33) падают
на одной и той же инструкции, побайтно идентичной во всех
сборках. Все три — сетевые партии на карте приключений.
Дефект стабилен между версиями: функция смещается по образу,
но код case 98 не меняется.

7. Первопричина
---------------
A0_MapCell_GetSetup (h3hota.exe, 0x4FD280) возвращает
разные значения в зависимости от типа объекта на клетке:

    .text:004FD280  mov  eax, [ecx+1Eh]   ; object_type
    .text:004FD283  cmp  eax, 22h          ; тип 34 = герой
    .text:004FD286  jnz  short loc_4FD2B0
    ; для героя: возвращает hero_astr21620[setup].miu_setup
    .text:004FD295  mov  eax, ecx
    .text:004FD297  shl  eax, 6
    ...
    .text:004FD2A5  lea  eax, [ecx+eax*2+21620h]
    .text:004FD2AC  mov  eax, [eax+14h]   ; miu_setup героя
    .text:004FD2AF  retn

    ; для корабля (тип 8): возвращает индекс из boats_4dword4E3C1
    .text:004FD2B5  mov  ecx, [ecx]
    .text:004FD2BC  lea  edx, [ecx+ecx*4]
    .text:004FD2C5  mov  eax, [ecx+edx*8+14h]
    .text:004FD2C9  retn

    ; для остальных: возвращает setup_dword0 клетки
    .text:004FD2CA  mov  eax, [ecx]
    .text:004FD2CC  retn

Case 98 предполагает, что foreground-клетка всегда содержит
город, и результат GetSetup — индекс города. Но foreground-
клетка может содержать героя (тип 34), корабль (тип 8) или
другой объект. В этих случаях GetSetup возвращает значение,
не являющееся индексом города: для героя это miu_setup
(произвольное число), для корабля — индекс корабля.

Массив городов по адресу [game_state + 0x21614] содержит
не более ~48 элементов (ограничение числа городов на карте).
Наблюдаемые индексы 91, 141, 167 многократно превышают
этот предел, и чтение выходит за границы выделения.

Соседние case (42/53, 17/20, 33, 87) используют тот же
паттерн (Get_Fore_Cell -> GetSetup -> индекс в массиве),
но обращаются к другим массивам ([game_state+0x4E38C],
[game_state+0x4E39C], [game_state+0x4E3AC]) с другими
шагами. Ни один из этих путей не проверяет границы.

8. Условия сбоя
---------------
Обязательные условия:
    - Сетевая или одиночная игра на карте приключений
    - Обработка case 98 (EBX = 0x62) в HD-моде
    - Foreground-клетка содержит объект НЕ город
      (герой, корабль, декоративный объект)
    - Результат GetSetup превышает размер массива городов

Наблюдаемые условия:
    - Все 3 дампа: сетевая игра (Network Game = 1)
    - День 3-4 — активная фаза игры с героями на карте
    - Graphics.Mode: 5 и 7 — не влияет на механизм
    - Карты: разные (Gshka, {Default}, Legacy) — не зависит
      от конкретной карты

11. Воспроизведение вылета
--------------------------
Условие активации пути:
    - Запустить сетевую или одиночную игру на карте
      с несколькими городами и героями
    - Дождаться обработки case 98 HD-модом (событие
      карты приключений, связанное с декоративными
      объектами — точный триггер определяется
      содержимым клетки)

Базовый сценарий:
    - Сетевая партия, 2+ игроков
    - Карта с городами и героями, активно
      перемещающимися по карте
    - День 3-4 (герои рядом с городами и
      декоративными объектами)

Варьирование:
    - Graphics.Mode: не влияет (наблюдались 5 и 7,
      в падающем коде нет ветвления по режиму)
    - Версия HD-мода: дефект стабилен (R23, R29, R33)
    - Карта: не зависит (3 разные карты в 3 дампах)

Дифф-тест:
    - Сравнить поведение case 98 при foreground-клетке
      с городом vs с героем: для города GetSetup вернёт
      допустимый индекс, для героя — miu_setup (выход
      за границы)

Достоверность и ограничения
---------------------------
Подтверждено:
- Инструкция краха и адресная арифметика —
  совпадение по всем 3 дампам
- Побайтная идентичность кода case 98 в трёх сборках
  (R23, R29, R33) — функция смещается, код не меняется
- Регистровые инварианты: EBX=0x62, ESI=0x699538 —
  стабильны по всем дампам
- Массив [game_state+0x21614] — массив городов (подтверждено
  по h3hota.exe: stride 0x168, вызов A0_Town_GetTypeName,
  имя towns_list_4dword21610)
- A0_MapCell_GetSetup возвращает НЕ индекс города для
  объектов типа 34 (герой) и 8 (корабль) — прочитано
  в листинге h3hota.exe (0x4FD280-0x4FD2CC)
- Соседние case (42/53, 17/20, 33, 87) используют тот же
  паттерн без проверки границ — прочитано в листинге R33
- sub_101AE10 — замена A0_AdvMgr_Draw_Minimap (хук
  на 0x412BA0, регистрация в sub_1034EC0+2991)
- Оригинальный код SoD (0x412F7D-0x412FC1) содержит
  функционально идентичный паттерн без проверки границ
- 0x6AAD18 = A0_GamePal_16 (16-битная палитра),
  byte_1 структуры города = индекс цвета для миникарты

Ограничения:
- Минидампы сокращённые (без кучи): содержимое массива

ВЫВОД
-----
Вылет HD_HOTA.dll+0x1BD83 (и плавающие адреса +0x1BB83,
+0x1AEF3 в сборках R29, R23) — выход за границы массива
городов при отрисовке миникарты.

HD-мод замещает функцию миникарты SoD (A0_AdvMgr_Draw_
Minimap_sub_412BA0) собственной версией (sub_101AE10).
Case 98 таблицы переходов получает foreground-клетку
и вызывает A0_MapCell_GetSetup, результат которого
используется как индекс массива городов, а прочитанный
байт — как индекс цвета в палитре. GetSetup возвращает
индекс города только для клетки с городом; для героя
(тип 34) возвращается miu_setup героя, для корабля
(тип 8) — индекс корабля. Эти значения не ограничены
размером массива городов, и при достаточно большом значении
чтение выходит за границы выделения.

Дефект унаследован из движка SoD: оригинальный код
A0_AdvMgr_Draw_Minimap (h3hota.exe, 0x412F7D-0x412FC1)
содержит функционально идентичный паттерн без проверки
границ. HD-мод воспроизводит логику движка.

Дефект присутствует минимум в трёх версиях HD-мода
(R23, R29, R33) и не зависит от графического режима,
конкретной карты или числа игроков. Все наблюдаемые
вылеты — в сетевой игре на карте приключений.
