АНАЛИЗ ВЫЛЕТА HD_TC2.dll+0x5BF5
====================================

Модель: Qwen 3.8
Дата: 31.07.2026
Заключение: HD_TC2.dll — чтение за концом буфера-источника при блите курсора мыши (цветовой ключ). Блит доверяет размерам, переданным вызывающим кодом; источник (спрайт курсора) исчерпан до границы страницы.

КРАТКОЕ РЕЗЮМЕ
--------------
Вылет происходит при смене кадра курсора мыши. Игра через HD-мод вызывает
блит с цветовым ключом в HD_TC2.dll (модуль True32). Блит копирует пиксели
спрайта курсора на поверхность курсора, пропуская прозрачные (ключ = 0).
Цикл блита читает пиксель из буфера-источника по адресу [EDI+EAX], и этот
адрес оказывается за пределами выделенной памяти — ровно на границе
страницы. Оба дампа подтверждают: ширина спрайта 44 пикселя, и именно
последние пиксели строки не помещаются в буфер.

Корень не в самом блите (он честно ограничивает область переданными
размерами), а в том, что размеры или указатель источника не соответствуют
реальному буферу. Это зона ответственности слоя управления поверхностями
(HD_HOTA.dll / hota.dll), а не HD_TC2.dll.

1. Исходные данные
------------------
Версия HotA: 1.8.0
Версии HD-мода: 5.7 R34, 5.6 R37
Класс сбоя: чтение/запись за концом буфера
Полезность лога для исправления: СРЕДНЯЯ
Уникальных вылетов: 2
Подсистема: отрисовка курсора мыши

Дамп 1: HD 5.7 R34, одиночная партия, Day = 6 3 6, Graphics.Mode = 7,
разрешение 1536x864.
Дамп 2: HD 5.6 R37, сетевая партия, Day = 1 1 7, Graphics.Mode = 7,
разрешение 2360x1328. Комментарий: только автотекст репортёра, показаний
игрока нет.

Оба: Graphics.Mode = 7 (внутренние 32 бит, stretchable), HotA 1.8.0,
один и тот же модуль HD_TC2.dll (RVA точки входа 0xE8A7, размер 0x3CF000).

2. Точка сбоя
-------------
Инструкция краша (HD_TC2.dll, imagebase 0x2000000):

    .text:02005BF5  mov     ecx, [edi+eax]

Цикл блита с цветовым ключом в sub_2005B30:

    .text:02005BF5  loc_2005BF5:
    .text:02005BF5      mov     ecx, [edi+eax]   ; чтение пикселя из источника
    .text:02005BF8      cmp     ecx, [ebp+arg_4] ; сравнение с цветовым ключом
    .text:02005BFB      jz      short loc_2005BFF
    .text:02005BFD      mov     [eax], ecx       ; запись в приёмник
    .text:02005BFF  loc_2005BFF:
    .text:02005BFF      add     eax, 4           ; следующий пиксель
    .text:02005C02      sub     edx, 1           ; счётчик ширины
    .text:02005C05      jnz     short loc_2005BF5

EDI после `sub edi, esi` = (источник - приёмник); EAX = текущий пиксель
приёмника. Сумма EDI+EAX = текущий пиксель источника.

3. Адресная арифметика
----------------------
Дамп 1:
- EAX = 0x05CB9EB8, EDI = 0x03195148
- EDI + EAX = 0x08E4F000 = адрес сбоя (read of address: 0x08E4F000)
- ESI = 0x05CB9E40 (приёмник, начало строки)
- Смещение в строке: EAX - ESI = 0x78 = 30 пикселей пройдено
- EDX = 14 пикселей осталось; полная ширина = 30 + 14 = 44

Дамп 2:
- EAX = 0x063688B8, EDI = 0x1D38B748
- EDI + EAX = 0x236F4000 = адрес сбоя (read of address: 0x236F4000)
- ESI = 0x06368810 (приёмник, начало строки)
- Смещение в строке: EAX - ESI = 0xA8 = 42 пикселя пройдено
- EDX = 2 пикселя осталось; полная ширина = 42 + 2 = 44

Оба адреса сбоя кратны 0x1000 (граница страницы 4 КБ) — чтение
обращается к первой невыделенной странице сразу за буфером.

4. Регистровые инварианты
-------------------------
    Регистр   Дамп 1        Дамп 2        Роль
    --------  ------------  ------------  -------------------------
    EAX       0x05CB9EB8    0x063688B8    текущий пиксель приёмника
    ECX       0x00000000    0x00000000    цветовой ключ (0 = прозрачный)
    EDX       0x0000000E    0x00000002    остаток ширины (счётчик)
    EBX       0x00000002    0x00000010    остаток высоты (строки)
    ESI       0x05CB9E40    0x06368810    приёмник, начало строки

ECX = 0 в обоих: цветовой ключ = 0 (прозрачный чёрный). Ширина блита
одинакова (44 пикселя) — один и тот же спрайт курсора.

5. Цепочка вызовов
------------------
Общая для обоих дампов (по V2):

    h3hota.exe  A0_MouseMgr_Set_Mouse_Cursor_sub_50CEA0
      call A0_MouseMgr_SetMouseCursorFrame_sub_50DAB0  (0x50CF4B)
        HD_HOTA.dll (перехватчик, версия-зависимый offset)
          hota.dll  sub_10076B00  (обёртка виртуального вызова)
            HD_TC2.dll  sub_2005B30  (блит с цветовым ключом)
              КРАШ: mov ecx, [edi+eax]

Возврат из HD_TC2 на hota.dll+0x76B81 (оба дампа, один offset):

    .text:10076B7A      call    dword ptr [edx+2Ch]  ; таблица функций
    .text:10076B7D      mov     ecx, esi             ; this = поверхность
    .text:10076B7F      call    eax                  ; вызов блита
    .text:10076B81      pop     esi                  ; возврат сюда

hota.dll получает указатель функции блита через таблицу (vtable[0x2C]
глобального объекта dword_106349DC) и вызывает его, передавая поверхность
курсора как this (ECX = ESI = аргумент_4).

6. Механизм сбоя
----------------
sub_2005B30 — блит с цветовым ключом и отсечением. Принимает 11
аргументов (retn 2Ch): координаты, ширину, высоту, указатели буферов,
шаги строк, границы отсечения, цветовой ключ.

Отсечение ограничивает область:
- ширина: x_смещение + ширина <= arg_1C (ширина источника)
- высота: y_смещение + высота <= arg_20 (высота источника)

Указатель источника: this->field_30 + this->field_2C * строка + столбец * 4,
где this->field_2C — шаг строки, this->field_30 — начало пиксельных данных.

Сбой: отсечение пропустило область, которая выходит за реальный буфер.
Последние пиксели строки (14 в дампе 1, 2 в дампе 2) попадают на
невыделенную страницу. Буфер источника заканчивается ровно на границе
страницы (адреса ...F000 и ...4000).

7. Первопричина
---------------
Блит доверяет переданным размерам и указателю поверхности. Источник
(спрайт курсора) исчерпан: либо буфер освобождён/пересоздан меньшего
размера (указатель this->field_30 устарел), либо переданные границы
отсечения (arg_1C/arg_20) превышают реальное выделение.

Различить эти варианты по сокращённому минидампу невозможно — нужно
состояние объекта-поверхности (this->field_2C, this->field_30, реальный
размер выделения), которое даёт только полный дамп.

Ответственность: слой управления поверхностями (HD_HOTA.dll / hota.dll),
который создаёт/пересоздаёт поверхность курсора и передаёт её геометрию
в блит. HD_TC2.dll лишь исполняет контракт.

8. Условия сбоя
---------------
- Graphics.Mode = 7 (внутренние 32 бит, stretchable) — оба дампа
- Путь True32 (HD_TC2.dll) активен именно в 32-битных режимах
- Смена кадра курсора мыши (A0_MouseMgr_SetMouseCursorFrame)
- Не зависит от режима игры: одиночная (дамп 1) и сетевая (дамп 2)
- Не зависит от дня партии: 6 3 6 и 1 1 7
- Версии HD-мода: 5.6 R37 и 5.7 R34 — модуль HD_TC2.dll одинаков

11. Воспроизведение вылета
--------------------------
Условие активации пути: Graphics.Mode из множества {4, 5, 7}
(внутренние 32 бита) — путь True32 (HD_TC2.dll). В режимах с внутренней
глубиной 16 бит ({0, 1, 2, 3, 6}) используется другой блит-модуль.

Базовый сценарий:
- Запустить партию (одиночную или сетевую) с Graphics.Mode = 7
- Выполнять действия, вызывающие смену кадра курсора (перемещение
  мыши по интерфейсу, смена контекстных курсоров)
- Краш недетерминирован: зависит от состояния буфера поверхности
  курсора в момент блита

Вероятностный характер: сбой привязан к состоянию буфера (освобождение/
пересоздание поверхности курсора при смене кадра). Точный триггер —
момент, когда указатель данных поверхности не соответствует реальной
области выделения. Без полного дампа детерминированный сценарий
не построить.

Дифф-тест: сравнить поведение при Graphics.Mode = 7 (True32) и
Graphics.Mode = 3 (внутренние 16 бит, тот же stretchable-вывод).
Если в режиме 3 краш не воспроизводится — подтверждается привязка
к пути True32.

Достоверность и ограничения
---------------------------
Подтверждено:
- Механизм сбоя доказан арифметикой: EDI+EAX = адрес сбоя в обоих дампах
- Инструкция краша на границе инструкции листинга (отрицательный тест)
- Цепочка вызовов подтверждена V2 (hota.dll+0x76B81, HD_TC2+0x5BF5)
- Вызывающий код в h3hota.exe идентифицирован (A0_MouseMgr_SetMouseCursorFrame)
- Ширина блита 44 пикселя в обоих дампах (один спрайт курсора)
- Адреса сбоя на границе страницы — чтение за концом выделения

Ограничения:
- Минидампы сокращённые (без кучи): состояние объекта-поверхности
  (this->field_2C, this->field_30, реальный размер) недоступно
- Развилка «указатель устарел vs размеры неверны» разрешается только
  полным дампом (Sys.FullDump = 1)
- Timestamp листинга HD_TC2.dll (30.07.2026) новее дампа 2 (05.04.2026);
  тождество подтверждено по RVA/размеру/границе инструкции, побайтно
  не сверялось
- HD_HOTA.dll: для дампа 2 (5.6 R37) листинг отсутствует; кадры
  HD_HOTA периферийны для диагноза (механизм полностью объяснён
  по HD_TC2 + hota + h3hota)

ВЫВОД
-----
Вылет в HD_TC2.dll+0x5BF5 — чтение за концом буфера-источника при
блите спрайта курсора мыши с цветовым ключом. Блит (sub_2005B30)
копирует 44-пиксельный спрайт курсора на поверхность курсора, пропуская
прозрачные пиксели (ключ = 0). Последние пиксели строки источника
попадают на невыделенную страницу: буфер заканчивается ровно на границе
страницы, и 14 (дамп 1) или 2 (дамп 2) пикселя читают за ним.

Корень — не в блите (отсечение ограничивает область переданными
размерами), а в несоответствии между переданной геометрией поверхности
и реальным буфером. Это зона слоя управления поверхностями HD-мода
(HD_HOTA.dll / hota.dll). Для точного разграничения вариантов
(устаревший указатель vs неверные размеры) нужен полный дамп
(Sys.FullDump = 1).
