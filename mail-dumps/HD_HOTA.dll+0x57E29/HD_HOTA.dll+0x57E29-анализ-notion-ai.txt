АНАЛИЗ ВЫЛЕТА  HD_HOTA.dll+0x57E29  чат HD-мода, таймер окна
================================================================================

    Заключение: HD_HOTA.dll: указатель таблицы методов искажён в одном бите


КРАТКОЕ РЕЗЮМЕ
--------------

    Игра упала сразу после нажатия кнопки игры, на вступительном видео.
    В этот момент оконная процедура HD-мода получила сообщение таймера
    0x00000113 с идентификатором 0x0000C4A1 и обратилась к объекту
    внутриигрового чата. Обработчик берёт объект из глобальной переменной,
    читает из него указатель на таблицу виртуальных методов и вызывает
    метод по смещению [+20h].

    Указатель таблицы оказался равен 0x035C197C, тогда как в этом запуске
    правильное значение - 0x03DC197C. Разница ровно в одном бите (бит 23,
    маска 0x00800000). Сумма 0x035C197C и смещения [+20h] даёт 0x035C199C -
    именно этот адрес стоит в логе как адрес неудавшегося чтения. По этому
    адресу в процессе не отображено ничего: все 122 модуля из дампа
    лежат в других диапазонах.

    Механизм восстановлен полностью, но источник искажённого значения -
    нет. В модуле есть единственная именованная запись этого поля, и она
    ставит константу текущего отображения; деструктор объекта пишет
    ту же константу обратно. Инструкции, которая гасила бы бит 23 маской,
    в листинге нет (0 совпадений на 925 064 строки, контроль метода
    пройден). Наиболее вероятное объяснение - случайное искажение одного
    бита (класс аппаратных сбоев); конкурирующая версия - указатель от
    другого отображения образа с базой 0x033C0000, которая даёт ту же
    разницу в один бит.

    Связанных вылетов в корпусе нет: адрес HD_HOTA.dll+0x57E29 встретился
    в 1 файле из 3544 просмотренных (это сам разбираемый лог), а в 850
    логах папки HD_HOTA.dll из 1393 файлов .txt он не встречается ни разу
    при 320 различных адресах вылета.

3. Точка сбоя
-------------

    Инструкция по адресу вылета - косвенный вызов виртуального метода:
    call dword ptr [eax+20h]. Перед ней по 0x01057E27 в EAX загружается
    указатель таблицы методов из первого поля объекта, а сам объект
    пришёл в ECX из глобальной переменной dword_12113B8 (чтение по
    0x01057DFC). Читаемая ячейка - слот таблицы по смещению [+20h]; в
    листинге этот слот заполнен и ведёт на реальный код:

    .rdata:0120199C                 dd offset sub_10474A0

    Байты по месту сбоя взяты из дампа и совпали с листингом, то есть код
    в рантайме не подменён - для среды с патчером это проверять обязательно:

    03C17E1D  A1 B0 13 DD 03    mov     eax, ds:03DD13B0
    03C17E22  83 38 00          cmp     dword ptr [eax], 0
    03C17E25  75 0B             jnz     short 03C17E32
    03C17E27  8B 01             mov     eax, [ecx]
    03C17E29  FF 50 20          call    dword ptr [eax+20h]

    Негодное значение - содержимое EAX: 0x035C197C. Правильный указатель
    таблицы в этом запуске - 0x03DC197C: в листинге таблица лежит по
    .rdata:0120197C, плюс дельта отображения 0x02BC0000. Значения
    различаются ровно одним битом: 0x035C197C xor 0x03DC197C = 0x00800000,
    бит 23.

    Арифметика сбоя сходится: 0x035C197C плюс смещение [+20h] равно
    0x035C199C, и именно это адрес неудавшегося чтения из лога. Регистры:
    EAX 0x035C197C, ECX 0x07D7C9A0 (объект), ESI 0x0000C4A1 (идентификатор
    таймера), EDI 0x00000113 (номер сообщения), EDX 0x00000001,
    EBX 0x00000000, ESP 0x00199D40, EBP 0x00199D80.

    По адресу 0x035C199C в процессе нет отображённой памяти: ни один из
    122 модулей дампа не занимает диапазон 0x035Cxxxx; ближайшие соседи -
    BINKW32.DLL 0x00900000..0x0092B000 снизу и HD_MCR.dll
    0x03770000..0x03796000 сверху.


4. Цепочка вызовов и контекст
-----------------------------

    Аргументы обработчика прочитаны из кадра стека в дампе, а не угаданы: по
    EBP 0x00199D80 лежат сохранённый EBP 0x00199DA0, адрес возврата
    0x02A5D2DC, затем hWnd 0x001E042E, номер сообщения 0x00000113,
    wParam 0x0000C4A1 и lParam 0x00000000. Следующий кадр по 0x00199DA0 имеет
    адрес возврата 0x03772721, то есть HD_MCR.dll+0x2721, и те же четыре
    аргумента: сообщение шло по цепочке оконных процедур без изменений.

    Сообщение 0x00000113 - сообщение таймера, его wParam - идентификатор

    -> HD_HOTA.dll+0x2D1CB (надстройка HD-мода над циклом сообщений)

    -> HD_HOTA.dll+0x579F0 (sub_10579F0, обработка сообщений окна)
    -> HD_HOTA.dll+0x57E29 - ВЫЛЕТ: call dword ptr [eax+20h], EAX 0x035C197C


5. Первопричина
---------------

    Правильное значение первого поля объекта чата ставит единственная
    именованная запись в модуле - конструктор sub_107B260 (строки листинга
    206874-206975). Он выделяет объект через operator new(24h), заполняет
    поля (в том числе [+8h] значением 0xE0 и буфер от VirtualAlloc в [+20h]),
    пишет в первое поле константу off_120197C и сохраняет объект в глобале
    dword_12113B8. По именованным ссылкам у этого глобала 1 чтение и 1
    запись, других мест правки нет.

    Значит, 0x035C197C не могло быть записано этим кодом: константа
    конструктора после отображения даёт 0x03DC197C. Испорчен один бит уже
    готового значения в памяти, и инструкции, которая гасила бы бит 23 (and с
    маской 0xFF7FFFFF либо xor с 0x00800000), в листинге нет: 0 совпадений
    при полном проходе 925 064 строк. Контрольный образец в том же файле
    находится (маска 80000003h - 5 совпадений), то есть поиск работает и нуль
    настоящий.

    Отсюда две версии, обе совместимые с байтами из дампа:

    1) случайное искажение одного бита в памяти или при её чтении - обычная
       картина для неисправной оперативной памяти или разгона;
    2) в объекте лежал указатель на таблицу от другого отображения того же
       образа с базой 0x033C0000 (0x035C197C минус 0x20197C), например при
       повторной загрузке библиотеки по другому адресу.

    Отдельно в этом же коде виден настоящий дефект HD-мода: он данный вылет
    не объясняет, но создаёт похожие. Деструктор sub_1047510 освобождает
    буфер через VirtualFree, возвращает в первое поле ту же константу
    off_120197C, освобождает объект - и глобал dword_12113B8 не обнуляет.
    После разрушения объекта глобал остаётся висячим, а обработчик таймера
    читает его без проверки: проверяется только соседний dword_12113B0.

    Перехват в цепочке есть, но виновником он не является: оконная процедура
    HD_MCR.dll+0x2721 передаёт управление через трамплин 0x02A5D2DC в
    sub_10579F0, и все четыре аргумента окна доходят до обработчика без
    изменений - это сверено по двум соседним кадрам стека. Объект чата и его
    таблица методов через перехват не проходят: обработчик берёт их из
    глобальной переменной сам.


6. Условия сбоя
---------------

    Путь достижим в обычном одиночном запуске. Обработчик реагирует на
    сообщение таймера 0x00000113 с идентификатором 0x0000C4A1 и требует,
    чтобы соседний глобал dword_12113B0 указывал на нулевое значение: только
    тогда переход на loc_1057E32 не делается и управление идёт на вызов
    метода. В этом запуске условие выполнилось.

    Состояние игры по логу: HotA 1.8.0, HD-мод 5.7 R39, <Version> = 5007318;
    карта test.h3m, Day = 0 00, Network Game = 0, то есть партия ещё не
    началась; Show Intro = 1 и Bink Video = 0 - вступительное видео
    показывалось средствами игры; профиль #hota15, разрешение 1180 x 664,
    Graphics.Mode = 5, OpenGL.Wrapper.Version = 2; Windows 10 10.0.19041.
    Время вылета 11.08.2026 14:47:24; комментарий игрока: нажал играть,
    началась заставка и музыка, после чего вылет.

    Чтобы вылет случился, должны совпасть три вещи: таймер чата успел
    сработать в этот ранний момент; объект чата существовал (ECX указывал на
    0x07D7C9A0 - похожее на кучу значение); указатель таблицы в объекте
    отличался от правильного. Первые два условия штатные, третье - внешнее по
    отношению к коду модуля.


7. Воспроизведение вылета
-------------------------

    Гарантированных шагов нет: условие сбоя лежит вне логики кода, а сам
    адрес встретился 1 раз на 3544 просмотренных лога. Разумная попытка:
    тот же профиль #hota15, Show Intro = 1, карта test.h3m, и 20 подряд
    входов в игру с просмотром заставки до конца. Если повтора нет - это
    ожидаемо и само по себе поддерживает версию случайного искажения.

    Решает вопрос полный дамп с памятью процесса (в присланном мини-дампе
    область объекта не сохранена). В нём надо прочитать остальные поля
    объекта по 0x07D7C9A0:

    1) если поле [+8h] равно 0xE0 и указатель буфера в [+20h] лежит в
       отображённой области, а негодным оказался только указатель таблицы -
       подтверждается случайное искажение одного бита;
    2) если у всех указателей объекта разница с ожидаемыми значениями равна
       0x00800000 - подтверждается версия про второе отображение образа с
       базой 0x033C0000.

    Дополнительно: тест оперативной памяти на этой машине; проверка, не
    осталось ли в папке игры второго экземпляра HD_HOTA.dll, и лога
    обновления HD-мода на предмет повторной загрузки библиотеки.


8. Достоверность и ограничения
------------------------------

Подтверждено:

- Адрес вылета отображён в листинг той же сборки: Timestamp 6A780EFD в шапке
  листинга совпал с TimeDateStamp 0x6A780EFD у HD_HOTA.dll в дампе; HD_MCR.dll
  закрыт листингом с Timestamp 6A780EE8 и тем же значением в дампе.
- Инструкция сбоя - call dword ptr [eax+20h] по 0x01057E29 внутри sub_10579F0
  (смещение +0x439). Байты из дампа совпали с листингом на пяти инструкциях
  подряд, подмены кода в рантайме нет.
- Арифметика адреса сходится: 0x035C197C плюс смещение [+20h] равно
  0x035C199C - в точности адрес неудавшегося чтения из лога.
- Дельта отображения 0x02BC0000 подтверждена данными, а не только формулой:
  чтение 0x03DD13B0 в коде соответствует dword_12113B0 в листинге.
- Правильное значение указателя таблицы - 0x03DC197C: конструктор sub_107B260
  пишет в объект off_120197C, а слот [+20h] этой таблицы заполнен
  (.rdata:0120199C dd offset sub_10474A0), то есть при верном указателе вызов
  прошёл бы штатно.
- Негодное и правильное значения различаются ровно одним битом: xor даёт
  0x00800000 (бит 23).
- Путь доставки сообщения прочитан по кадрам стека в дампе: hWnd 0x001E042E,
  сообщение 0x00000113, wParam 0x0000C4A1, адреса возврата 0x02A5D2DC и
  0x03772721 (HD_MCR.dll+0x2721).

Ограничения:

- Источник искажения не установлен: случайное искажение бита и указатель от
  отображения с базой 0x033C0000 дают одинаковые байты, а различающих их
  данных в этом дампе нет.
- Дамп минимальный, 95.6 КБ: сохранены 33 диапазона памяти общим объёмом
  46.8 КБ, область объекта 0x07D7C9A0 в них не попала, поэтому остальные поля
  объекта прочитать нельзя.
- Шаг 0x02A5D2DC - код, созданный патчером в рантайме; ни модуля, ни листинга
  для него нет, содержимое трамплина проверить нечем.
- Поиск по корпусу шёл только по файлам .txt, содержимое файлов .dmp текстом
  не просматривалось; в одном из поисков обход прерван на 3438 из 3544 файлов
  (знаменатель 3544 - все файлы .txt папки mail-dumps, не просмотрено 106).
- Вылет не воспроизводился: разбор целиком статический, по логу, дампу и
  листингам.

Отрицательные результаты:

- Инструкция, гасящая бит 23: искали маску 0FF7FFFFFh и xor с 800000h по
  листингу HD_HOTA.dll - 0 совпадений; покрытие полное, файл пройден
  целиком (925 064 строки, 1 файл из 1). Контрольный образец в том же файле
  найден (маска 80000003h - 5 совпадений), то есть поиск работает и нуль
  настоящий.
- Вторая запись в глобал объекта чата: у dword_12113B8 по именованным
  ссылкам 1 запись и 1 чтение на тот же полный проход листинга; больше
  никто переменную не правит.
- Похожие вылеты в корпусе: адрес HD_HOTA.dll+0x57E29 - 1 файл из 3544
  просмотренных (это сам разбираемый лог); в 850 логах папки
  HD_HOTA.dll из 1393 файлов .txt адрес не встречается ни разу при 320
  различных адресах вылета; знаменатель всех дробей здесь - просмотренные
  файлы .txt корпуса (частый сосед для сравнения: +0x2AD39 -
  117 логов, 13.8 процента).
- Спутники этого вылета: wParam 0x0000C4A1, кадр HD_MCR.dll+0x2721 и
  EDI 0x00000113 - по 1 файлу из 3544 каждый, то есть только сам лог.
- Упоминания заставки в комментариях игроков: 0 файлов из 3544, привязать
  вылет к показу видео по чужим логам не удалось.
- Отображённая память по 0x035Cxxxx: 0 модулей из 122 в списке дампа и 0
  диапазонов из 33 сохранённых.
