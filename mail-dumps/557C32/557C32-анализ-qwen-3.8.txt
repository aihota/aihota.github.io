АНАЛИЗ ВЫЛЕТА 557C32
================================================================================

Модель: Qwen 3.8
Дата: 31.07.2026
Заключение: виновник — h3hota.exe; пропущена проверка NULL на пути раннего
возврата при записи в выходной указатель out_msg_was_recieved.

КРАТКОЕ РЕЗЮМЕ
--------------
Функция приёма сетевых сообщений A0_NetMsgProcessor_RecieveNetMsg_sub_557C10
получает от вызывающего кода нулевой указатель out_msg_was_recieved (EDI = 0).
Первая запись по этому указателю (0x557C1E) защищена проверкой test edi, edi,
но вторая запись — на пути раннего возврата при in_dauther_dlg != 0 и
наличии отложенного сообщения (this->field_8 != 0) — проверку пропускает.
Родственный путь (0x557C6B) ту же запись выполняет С проверкой. Все 4 вылета
— сетевые партии, во всех in_dauther_dlg = 1 и field_8 != 0.

Операция: write of address: 0x00000000

EDI = 0x00000000 (во всех 4 дампах)

Проверка: base(EDI) + offset(0) = 0x00000000 == faulting address. Совпадение.

HD_HOTA явно передаёт NULL (push 0) и 1 (push 1). Вызов через
абсолютный адрес h3hota.exe (mov eax, 553BA0h; call eax) —
признак репликации логики движка. A0_NetMgr_Get_Processor

В стеке V2 общих кадры h3hota.exe: 0x005FFACB

через который HD_HOTA перехватывает управление.

Подсистема: обработка сетевых сообщений (приём в диалоговом режиме).

6. Классификация сбоя
---------------------
Класс: разыменование нулевого указателя (запись по адресу 0).
Механизм: пропущенная проверка NULL на одном из двух путей записи
в выходной указатель out_msg_was_recieved.

7. Группировка дампов
---------------------
Все 4 вылета — один механизм. Регистровые инварианты:

    Параметр             Дампов  Значение
    -------------------  ------  ------------------------------------
    EDI (faulting addr)  4       0x00000000 (NULL)
    in_dauther_dlg (CL)  4       0x01 (восстановлено: ECX = ESI|0x01)
    EAX (this->field_8)  4       != 0 (отложенное сообщение)
    Network Game         4       1

Восстановление in_dauther_dlg: при входе mov esi, ecx сохраняет this
в ESI; затем mov cl, [ebp+in_dauther_dlg] перезаписывает младший байт
ECX. Во всех дампах ESI = this (старшие 3 байта ECX), CL = 0x01.

8. Механизм сбоя
----------------
Вызывающий код передаёт out_msg_was_recieved = NULL (корректный вызов —
функция ШТАТНО обрабатывает NULL в первой проверке 0x557C1A). При
одновременном выполнении двух условий:

- this->field_8 != 0 (есть отложенное сообщение о закрытии боя,
  установленное A0_BattleMgr_Main через Set_CloseMsg);
- in_dauther_dlg != 0 (вызов в диалоговом режиме);

функция идёт по пути раннего возврата (0x557C32) и пишет
*out_msg_was_recieved = 1 БЕЗ проверки NULL. Родственный путь (0x557C6B,
приём из сети) ту же запись выполняет С проверкой test edi, edi.

Дефект — пропущенная проверка в h3hota.exe (код движка, не HD-мода).
HD-мод лишь диспетчирует вызов через свои перехватчики.

9. Условия сбоя
---------------
- Сетевая партия (Network Game = 1) — все 4 дампа.
- Бой (или его завершение): A0_BattleMgr_Main устанавливает field_8
  через Set_CloseMsg — отложенное сообщение о закрытии боя.
- Диалоговый режим: in_dauther_dlg = 1 (вызов из диалогового
  диспетчера, а не из основного цикла).
- out_msg_was_recieved = NULL: вызывающий код не запрашивает флаг
  приёма (корректный вызов, функция обязана это обрабатывать).
- День партии: от 1 2 5 до 3 3 6 (середина игры, не предыгровое
  состояние).

11. Воспроизведение вылета
--------------------------
Условие активации пути: сетевая партия + бой + диалоговый вызов
RecieveNetMsg с NULL out_msg_was_recieved при отложенном сообщении
о закрытии боя (field_8 != 0).

Базовый сценарий:

- Запустить сетевую партию (Network Game = 1), минимум 2 игрока.
- Дойти до боя (или дождаться завершения боя — именно тогда
  A0_BattleMgr_Main выставляет field_8 через Set_CloseMsg).
- В момент закрытия боя (или сразу после) вызвать диалоговое окно
  (напр. окно информации о сценарии, правый клик по объекту).
  Диалоговый диспетчер вызывает RecieveNetMsg с in_dauther_dlg = 1
  и out_msg_was_recieved = NULL.
- Если field_8 ещё не сброшен (сообщение о закрытии не обработано),
  срабатывает путь 0x557C32 без проверки NULL — вылет.

Варьирование: тип карты и день не влияют (разные карты и дни
в 4 дампах). Graphics.Mode не влияет (в падающей функции нет
ветвления по графическому режиму). Версия HD-мода не влияет
(R33 и R34 — HD-мод лишь диспетчирует вызов).

Достоверность и ограничения
----------------------------
Подтверждено:

- Адресная арифметика: EDI = 0 = faulting address.
- Инструкция краша на границе инструкции в листинге.
- Entry point 0x639C00 совпадает — листинг той же сборки.
- Пропущенная проверка: путь 0x557C32 БЕЗ test edi, edi;
  родственный путь 0x557C6B С проверкой (цитаты в разделе 4).
- in_dauther_dlg = 1 восстановлено по ECX/ESI во всех 4 дампах.
- field_8 != 0 (EAX) во всех 4 дампах.
- Точный вызывающий код: HD_HOTA.dll (R34 sub_1185E20,
  R33 sub_1004F20) явно передаёт push 0 (NULL) и push 1
  через vtable[1] — прочитано по листингам обеих версий.
- Writer field_8: конструктор ставит 0 (0x557BAD),
  Set_CloseMsg (0x557CB6) — единственный writer nonzero,
  вызывается из A0_BattleMgr_Main (0x473EBB). Функция
  RecieveNetMsg сама сбрасывает field_8 в 0 (0x557C42).

Ограничения:

- Минидампы сокращённые (без кучи): содержимое объекта
  NetMsgProcessor (field_8, vtable) не проверить в отладчике.
  Значение field_8 подтверждено только регистром EAX.

ВЫВОД
-----
Вылет 0x00557C32 — разыменование нулевого указателя в функции приёма
сетевых сообщений A0_NetMsgProcessor_RecieveNetMsg_sub_557C10 (h3hota.exe).
HD_HOTA.dll явно передаёт out_msg_was_recieved = NULL и in_dauther_dlg = 1
(push 0; push 1; call vtable[1] — прочитано в листингах R33 и R34).
Функция корректно обрабатывает NULL на первом пути записи (0x557C1E,
с проверкой), но пропускает проверку на пути раннего возврата (0x557C32),
когда in_dauther_dlg != 0 и есть отложенное сообщение о закрытии боя
(field_8 != 0, устанавливает A0_BattleMgr_Main через Set_CloseMsg).
Родственный путь 0x557C6B ту же запись выполняет с проверкой. Дефект
унаследован от SoD (базовый класс NetMsgProcessor). Все 4 вылета —
сетевые партии, середина игры, разные карты и дни. Полезность лога
ВЫСОКАЯ: дефект локализован, механизм доказан полностью.
