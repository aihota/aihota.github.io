АНАЛИЗ ВЫЛЕТА  HD_HOTA.dll+0x1BE67  (отрисовка миникарты / таблица terrain DEF)
================================================================================

    Модель: GPT-5.6 Sol + Claude Opus 5
    Дата:   05.09.2026
    Заключение: HD_HOTA.dll разыменовал нулевой элемент terrain DEF после
    непроверенного индексирования байтом клетки карты.


КРАТКОЕ РЕЗЮМЕ
--------------

Что произошло:

    HD_HOTA.dll завершился при обновлении миникарты. Выбранный элемент
    таблицы terrain DEF оказался нулевым; следующая команда прочитала
    поле +0x20 и получила исключение 0xC0000005 по адресу 0x00000020.

Локальный механизм:

    Журнал, поток исключения, байты кода и точный листинг подтверждают
    цепочку MapCell+4 -> элемент land-def -> 0 -> чтение 0x20. Между
    индексированием, загрузкой элемента и разыменованием проверок нет.

Охват семейства:

    Полный поиск дал 4 физических журнала и 3 SHA-уникальных инцидента
    этой семантической точки в HD 5.7 R10, 5.7 R17 и 5.8 R8. Ещё один
    SHA-уникальный near-null случай относится к другой функции.

Граница доказанности:

    Уровень L1. Фактический байт земли, адрес элемента и первый источник
    нулевого состояния не сохранены. Различие movzx против movsx и путь
    с z=-1 остаются проверяемыми гипотезами, а не установленной причиной.

2. Проверка листинга и адреса
-----------------------------

Сверка листинга:

- HD_HOTA.dll-5.8-R8.txt; базовый адрес 0x01000000.
  SHA-256: 88f06be651a395fdc165d78260574dd24d916913f56739d6ff0a415b45d78d25.
  Метка времени 0x6A8F1466; размер образа 0x011FA000. Минидамп содержит
  HD_HOTA.dll по диапазону 0x041F0000..0x053EA000 с теми же метаданными.

Проверка нормализации:

    адрес во время выполнения    = 0x0420BE67
    база загрузки модуля         = 0x041F0000
    база образа листинга         = 0x01000000
    адрес в листинге             = 0x0420BE67 - 0x041F0000 + 0x01000000 = 0x0101BE67

Точный участок:

.text:0101BE57                 mov     ecx, [ebp+var_40]
.text:0101BE5A                 movzx   eax, byte ptr [esi+4]
.text:0101BE5E                 lea     eax, [ecx+eax*4]
.text:0101BE61                 mov     ecx, [ebp+var_54]
.text:0101BE64                 mov     eax, [eax+ecx]
.text:0101BE67                 mov     eax, [eax+20h]

Проверка байтов:

- В минидампе по 0x0420BE5A лежит последовательность
  0F B6 46 04 8D 04 81 8B 4D AC 8B 04 08 8B 40 20. Она кодирует тот же
  участок; последние три байта 8B 40 20 соответствуют mov eax,[eax+20h].

Регистры (полная версия) из потока исключения и TXT-журнала:

EAX=0x00000000  EBX=0x0000005C
ECX=0x00000504  EDX=0x0000005C
ESI=0x05486BDA  EDI=0x00000059
ESP=0x001A9C1C  EBP=0x001A9CC0
EIP=0x0420BE67


3. Точка сбоя
-------------

Локальный механизм:

- По адресу 0x0101BE64 загрузка выбранного элемента таблицы дала EAX=0.
  Команда 0x0101BE67 выполнила чтение dword [0x00000000+0x20], что точно
  совпадает с параметром исключения [1]=0x00000020.

Извлечённые значения:

    Значение                         Результат
    -------------------------------  ----------------
    AdvMgr / this                    0x08F51398
    LandDefShift                     0x00000504
    кандидат координат клетки        x=89, y=92, z=0
    исходный уровень из arg_8         -1
    указатель клетки                  0x05486BDA
    байт земли [клетка+4]             не захвачен
    выбранный элемент land-def        0x00000000
    адрес аварийного чтения           0x00000020

Интерпретация стека и регистров:

- Негодное значение - нулевой указатель, загруженный из элемента
  AdvMgr + 0x504 + 4*land_byte. Сам land_byte утрачен до исключения, поэтому
  нельзя честно выбрать между индексом вне диапазона, незагруженным ресурсом,
  освобождением или перезаписью элемента.

Схема механизма:

    MapCell* = 0x05486BDA
        -> сырой_тип_земли = byte [MapCell+4]
        -> slot = 0x08F51398 + 0x504 + 4*сырой_тип_земли
        -> DEF = dword [slot] = 0x00000000
        -> dword [DEF+0x20] = чтение 0x00000020 -> ВЫЛЕТ

-----------------------------

    -> h3hota.exe: A0_MainMgr_PlayMgr_sub_4B0BA0, игровой цикл
    -> HD_HOTA.dll: зарегистрированная замена advManager::UpdateRadar,
       sub_101B140
    -> sub_101B140+0xCCA: получение видимости клетки
    -> sub_101B140+0xD1A: выбор элемента land-def по MapCell+4
    -> sub_101B140+0xD27: mov eax,[eax+20h], ВЫЛЕТ

    Регистрация HotA подтверждает семантику аналога: sub_10182650 передаёт
    sub_10181050 в установщик замены при проверке HD.BPP. HD_HOTA отдельно
    регистрирует собственную реализацию для режима высокой чёткости.

    Сравнение с оригиналом SoD: A0_AdvMgr_Draw_Minimap_sub_412BA0 читает тот же
    байт клетки, но на 0x00412EC0 и 0x00412F61 преобразует его как знаковый.
    Это подтверждает расхождение семантики индекса, но без фактического байта
    текущей клетки не доказывает, что именно оно создало нулевой элемент.

    Сопутствующий подтверждённый дефект пути: arg_8 даёт var_58=-1. Для
    GetCell значение уровня зажимается до 0, но в A0_Get_CellParams_sub_4F8040
    передаётся исходное -1. Полученный бит видимости активировал ветку land-def,
    так как arg_14, arg_18 и arg_1C равны нулю. Не доказано, что при корректном
    z=0 бит был бы другим, поэтому это не объявляется источником нулевого слота.


5. Первопричина
---------------

Доказанный локальный дефект:

- HD_HOTA.dll использует сырой байт [MapCell+4] как беззнаковый индекс и между
  индексированием, загрузкой элемента и чтением DEF+0x20 не проверяет ни
  диапазон, ни нулевой результат. Полный разбор sub_101B140 нашёл 8 мест;
  проверены все 8, пропущено 0. В HotA sub_10181050 найдены все 3 аналога,
  но там применяется знаковое расширение. Оба варианта полагаются на внешний
  инвариант и не защищают потребителя.

Рабочая гипотеза:

- Наиболее сильная гипотеза - значение с установленным старшим битом, возможно
  0xFF, которое HD_HOTA расширяет через movzx. При 0xFF адрес был бы
  AdvMgr+0x900 = 0x08F51C98; знаковый вариант дал бы AdvMgr+0x500 =
  0x08F51898. Это только расчёт сценария: фактический байт в дампе отсутствует.
  Альтернативы - нулевой допустимый элемент, сбой загрузки ресурса, преждевременное
  освобождение или перезапись таблицы. Ни один производитель не подтверждён.

Исправление:

- В HD_HOTA.dll получать вместе со смещением фактическое число land-def,
  проверять сырой_тип_земли до умножения, затем проверять DEF и DEF+0x20. При ошибке
  записывать координаты, сырой байт, число элементов, смещение, адрес элемента
  и его значение, после чего применять безопасный цвет земли или пропускать
  пиксель. Для видимости использовать тот же проверенный z, что и для GetCell.

Дифференциальный тест:

- До исправления сохранённый триггер должен достигать 0x0101BE67 и падать.
  После исправления та же последовательность должна дать одну диагностическую
  запись и продолжить игру; обычная клетка каждого допустимого типа земли
  должна сохранить прежний цвет миникарты. Один только запрет чтения 0x20 без
  фиксации сырой_тип_земли и элемента считается маскировкой, а не подтверждением причины.


6. Условия сбоя
---------------

Сводка инцидентов:

Инцидент                     Версия                    Условие
---------------------------  ------------------------  --------------------------
incident-a64d3a2ed9157f3d    HD 5.7 R10 / HotA 1.8.0  NULL land-def, чтение 0x20
incident-90857fa1353b1994    HD 5.7 R17 / HotA 1.8.0  NULL land-def, чтение 0x20
incident-89c63dd7b9de8ed5    HD 5.8 R8 / HotA 1.8.1   NULL land-def, чтение 0x20

Вложения:

- R10: HD_HOTA.dll+0x1AAE7-1.8.0-1.txt.
- R17: HD_HOTA.dll+0x1ADD7-1.8.0-1.txt.
- R8: HD_HOTA.dll+0x1BE67-5.8-R8-181.dmp.

Общий контекст:

- Во всех 3 уникальных инцидентах EAX=0, ECX=0x504 и аварийное чтение равно
  0x20. Во всех трёх точный листинг показывает один семантический участок
  замены миникарты: movzx [cell+4] -> land-def slot -> [NULL+0x20].

Различающиеся условия:

- R10: одиночная игра, карта Bring me The King?s head.h3m, день 1 1 1.
- R17: сетевая игра, карта Fishy34,Phender,Cypher_JD ... SuperHero.h3m,
  день 2 4 5.
- R8: HotA 1.8.1; текущий журнал называет одну карту, а производный AUTOSAVE
  содержит имя Holzwagen,romanzo ... SuperHero.h3m. Это различие не смешивается
  с фактами момента исключения.

Показания и вложения:

- Только текущий R8 имеет DMP и AUTOSAVE.GM2. Для R10 и R17 DMP не найдено:
  ни одного из двух исторических уникальных инцидентов. AUTOSAVE создан после сбоя и имеет
  роль производного артефакта; исходная H3M не найдена, поэтому байт клетки из него не выводился.


7. Воспроизведение вылета
-------------------------

Роль 1 — тестер за игрой:

- На чистой копии соответствующей версии загрузить исходную карту или ближайший
  доступный сейв, включить HD.UI.HiRezCore и HD.Option.ColorMode, открыть экран,
  который обновляет радар, и повторять перемещение/обновление миникарты. Отдельно
  сравнить вызовы с уровнем -1 и 0. Зафиксировать сборку, карту, ход и результат.

Роль 2 — подтверждение причины:

- Поставить точки останова на 0x0101BE5A, 0x0101BE64 и 0x0101BE67.
  На каждой итерации записывать x, y, входной z, зажатый z, [cell+4],
  LandDefShift, число элементов во время выполнения, вычисленный адрес элемента и dword [slot].
  Аппаратное наблюдение на элемент включать только если индекс допустим, но
  значение становится нулевым. Отдельно сравнить возврат видимости для z=-1 и z=0.

Ожидаемый результат исправленной сборки:

- При 100 повторениях на том же триггере нет 0xC0000005; каждый недопустимый
  индекс или нулевой ресурс создаёт ровно одну запись и безопасно обрабатывается;
  допустимые типы земли дают те же цвета, что контрольная сборка.

Необходимая телеметрия:

- Версия модулей, номер потока, координаты, сырой_тип_земли, входной и нормализованный z,
  LandDefShift, число элементов, AdvMgr, адрес элемента, значение DEF, DEF+0x20,
  имя загружаемого ресурса и стек первого обнуления/освобождения.


8. Достоверность и ограничения
------------------------------

Матрица уверенности:

- Точка сбоя: подтверждена
- Локальный механизм: подтверждён
- Происхождение состояния: не установлено
- Охват семейства: подтверждён
- Уровень причинности: L1

Подтверждено:

- Адрес: 0x0420BE67 -> RVA 0x1BE67 -> 0x0101BE67, точная граница команды.
- Механизм обращения: элемент таблицы вернул 0 и последовало чтение 0x20.
- Текущий кадр: AdvMgr=0x08F51398, LandDefShift=0x504, var_58=-1,
  координатный кандидат x=89, y=92 и зажатый z=0.
- Семья: 3 уникальных инцидента среди 4 физических TXT; все 3 отображены на
  тот же семантический участок. Классифицированы все 4 уникальных кандидата.
- Перепись потребителей: все 8 мест HD_HOTA используют movzx; все 3 места
  HotA используют movsx; пропущено 0.
  у перечисленных мест отсутствуют локальные проверки диапазона и NULL.

Отрицательные результаты:

- Полный обход 5509/5509 сырых TXT нашёл точный текущий RVA в 1 файле; контрольный
  текущий журнал найден. Обход 1688/1688 HD_HOTA TXT нашёл 6 физических чтений
  0x20, то есть 4 SHA-уникальных события; 4 файла и 3 уникальных события принадлежат
  этой семье. Ограничение результатов отсутствует, пропущено 0.
- В обычном минидампе нет диапазонов памяти клетки 0x05486BDA, AdvMgr 0x08F51398 и
  таблицы land-def: сырой индекс восстановлен в ни в одном текущем DMP.
- Исходная карта с именем из AUTOSAVE не найдена при проверке единственного
  имени; версия-зависимый декодер клетки отсутствует. AUTOSAVE не использован
  как факт момента вылета.
- Для двух исторических уникальных членов семьи DMP не найдено: ни одного из двух.

Ограничения:

- CONTEXT_THREAD_MISMATCH запрещает приписывать кадр потоку 14932 без оговорки.
  Значения команды пригодны; происхождение локальных слотов остаётся условным.
- Не захвачены сырой_тип_земли, число элементов во время выполнения,
  адрес выбранного элемента, AdvMgr, куча и история ресурсов. Управляемого повтора нет.
- Поэтому глубина L1: производитель некорректного состояния и полная первопричина
  не установлены. Утверждение о 0xFF и signedness остаётся проверяемой гипотезой.


ВЫВОД
-----

Контрольный расчёт:

    базовое значение = AdvMgr 0x08F51398
    смещение поля = 0x504 + 4*сырой_тип_земли; сырой_тип_земли не захвачен
    эффективный адрес = 0x08F51398 + 0x504 + 4*сырой_тип_земли; dword по нему был 0
    инструкция = mov eax,[eax+20h], фактическое чтение 0x00000020

Происхождение состояния:

    Установлена только граница потребителя: нулевое значение пришло из элемента
    таблицы land-def, выбранного байтом клетки. Первый неверный индекс, загрузчик,
    обнуление, освобождение или перезапись не попали в артефакты.

Действия:

    Адресат: разработчик HD-мода.

    - В sub_101B140 и версиях-аналогах добавить проверку сырой_тип_земли по фактическому
      числу terrain DEF, проверку DEF/DEF+0x20 и единый нормализованный z до доступа.
    - Повторить три семейных сценария и положительный контроль; сохранить указанную
      телеметрию и доказать, что корректные цвета не изменились, а неверное состояние
      не доходит до чтения [NULL+0x20].

Критерий завершения:

    Исправление считается подтверждённым после управляемого A/B-повтора с захватом
    фактического сырой_тип_земли и производителя нулевого элемента. До этого отчёт остаётся
    на L1, даже если защитная проверка устраняет падение.
