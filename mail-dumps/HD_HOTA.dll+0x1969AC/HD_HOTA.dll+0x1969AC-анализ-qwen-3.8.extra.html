Визуализация вылета

Рабочий буфер клеток карты зарождается как ноль в момент отказа operator new и без проверки доходит до цикла копирования: первая же запись попадает в адрес 0x0. Источник данных (клетка карты) при этом исправен — бит именно приёмник.

A call esi (0x617492) operator new размер (слоёв+1)·W·H·38 EAX = 0 (отказ)
B mov [var_C], eax var_C = 0 проверки на ноль нет
C add edx, [var_C] EDX = 0 + 0·38 первая итерация
D mov [edx], ecx запись [0x0] адрес сбоя
S A0_GameMap_GetCell ESI = 0x16610024 клетка жива, ECX = 0xFFFFFFFF
Источник (S) отдаёт корректную клетку карты; нулевой путь (A–D) — это буфер-приёмник, а не данные.
A Функция просит у operator new (h3hota.exe, 0x617492, сводится к _nh_malloc) буфер под копию карты. При нехватке памяти распределитель возвращает ноль — в EAX приходит 0.
B Результат сохраняется в var_C без проверки. Единственное условие после выделения (add ecx,1; jz) проверяет число слоёв карты, а не указатель.
C Адрес приёмника считается как var_C + индекс·38. На первой итерации индекс нулевой (EBX = 0, EDI только что увеличен с 0 до 1), поэтому EDX = var_C = 0.
D Первая запись mov [edx], ecx идёт по адресу EDX + 0 = 0x0 — нарушение доступа на запись. Это и есть адрес сбоя из поля Information.
S Контраст: данные даёт A0_GameMap_GetCell (ESI = 0x16610024 — живой указатель в кучу). Записываемое значение ECX = 0xFFFFFFFF — первые 4 байта исправной клетки; поставщик данных не повреждён.
