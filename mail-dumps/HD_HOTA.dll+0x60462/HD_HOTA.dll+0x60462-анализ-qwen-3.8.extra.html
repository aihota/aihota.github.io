Визуализация вылета

Указатель на объект диалога (this, передаётся в ECX) зарождается как ноль в функции-перехватчике лобби и без единой проверки проходит всю цепочку вызовов до падающей функции. Штатный диспетчер того же уведомления передаёт валидный объект под проверкой — это контраст, показывающий аномальность нулевого пути.

A sub_1077070 this = NULL xor ecx, ecx
B sub_106FDD0 case 23 this = NULL
C sub_106A570 [ebp-44h] this = NULL
D sub_106FDD0 case 11 this = NULL
E sub_1060640 ECX без изменений this = NULL
F sub_1060430 EBX = 0 mov eax,[ebx+48h] [0x48] — краш
G sub_1070310 this = var_7C под проверкой
Штатный путь (G) диспетчит то же уведомление с валидным объектом; проблемный путь (A–F) — с нулевым указателем.
A Функция-перехватчик лобби: инструкция xor ecx, ecx кладёт в this ноль, хотя валидный объект есть в EDI и используется выше по функции.
B Оконная процедура лобби, case 23: ноль проходит транзитом, ECX не переопределяется.
C Диспетчер сохраняет ноль в локальную переменную [ebp-44h] и передаёт его дальше.
D Повторный вход в оконную процедуру, case 11: this по-прежнему ноль.
E Ноль уходит в падающую функцию без переопределения ECX.
F Падающая функция обнуляет EBX (ветка при this == NULL) и читает [ebx+48h] = [0x48] — адрес сбоя.
G Контраст: штатный диспетчер того же уведомления передаёт валидный объект под проверкой test eax,eax; jz.
