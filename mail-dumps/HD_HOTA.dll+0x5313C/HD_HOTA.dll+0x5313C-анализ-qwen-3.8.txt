КРАТКОЕ РЕЗЮМЕ
--------------
Глобальный указатель управляющего блока кольцевой очереди сообщений повреждён в обоих дампах, но РАЗНЫМИ значениями: в R33 это фрагмент ASCII-текста 0x63653236 («62ec»), в R35 — ноль. В R33 ненулевой мусор проходит проверку на NULL и падает на разыменовании; в R35 ноль пропускает разыменование, но падает на следующей инструкции `[eax+8]` (проверка на NULL неполная — пропускает только одно разыменование, не весь путь). Оба вылета — в одной функции извлечения из очереди, в одном контексте: сетевая игра, Jebus Cross, день 1 11, Graphics.Mode = 5. Источник порчи глобала статически не определяется — нужен полный минидамп или аппаратная точка останова.

Значение 0x63653236 (R33) в little-endian: байты 36 32 65 63 = ASCII «62ec» — текстовые данные, не адрес кучи.

5. Первопричина
---------------
Функция sub_1053100/sub_1053480 — извлечение элемента из кольцевой очереди (ring buffer pop). Код идентичен в R33 и R35:

- Проверка атомарных счётчиков (активна ли система)
- lock xadd: атомарное чтение счётчика ссылок
- cmp count, 0: проверка числа элементов
- mov eax, global_ptr: загрузка указателя на управляющий блок
- test eax, eax / jz: проверка на NULL (НЕПОЛНАЯ)
- mov eax, [eax]: чтение первого поля (само-ссылка на область глобалов)
- [eax+8]: ёмкость, [eax+4]: массив
- Индекс: (count - 1) & mask
- memmove: копирование данных, освобождение элемента
- sub count, 1: декремент счётчика

Два пути вылета (один дефект глобала, разные значения порчи):

Путь A (R33): глобал = 0x63653236 (ASCII-мусор, ненулевой). Проверка `jz` НЕ срабатывает -> `mov eax, [eax]` читает по адресу 0x63653236 -> нарушение доступа.

Путь B (R35): глобал = 0x00000000 (NULL). Проверка `jz` срабатывает, пропускает `mov eax, [eax]`, EAX остаётся 0. Следующая инструкция `mov ecx, [eax+8]` читает [0x8] -> нарушение доступа.

Неполная проверка на NULL — вторичный дефект кода: `jz` должен вести на выход с ошибкой (как при count=0), а не на продолжение работы с EAX.

Управляющий блок создаётся в sub_1001220 (инициализация): operator new(8) -> global_ptr = eax; [eax] = &global_ptr (само-ссылка); [eax+4] = 0. Освобождение в sub_11E9300 (atexit): free(global_ptr); global_ptr = 0. Счётчик элементов (count) НЕ обнуляется.

Push-функция sub_1080570 обращается к глобалам массива/ёмкости/счётчика НАПРЯМУЮ (без индиректа через global_ptr), поэтому push-путь не страдает от коррупции указателя.

Повреждение глобального указателя в .data-секции HD_HOTA.dll. Два дампа — два РАЗНЫХ значения порчи одного глобала:
- R33: 0x63653236 (ASCII «62ec») — перезапись строковыми данными
- R35: 0x00000000 (NULL) — обнуление (порча нулём или преждевременная очистка)

Значение NULL в R35 допускает дополнительную гипотезу: atexit-очистка обнуляет указатель, но НЕ обнуляет счётчик. Если очистка прошла при непустой очереди, следующий pop упадёт на [NULL+8]. Однако вылет происходит СЕРЕДИНЫ игры (Day 1 11, партия активна), не при выходе — atexit не должен выполняться. Основная гипотеза — порча из неустановленного кода.

Статический анализ не определяет источник порчи:
- Прямые writer'ы глобала: только init (operator new) и cleanup (mov 0) — оба корректны
- Соседние переменные .data — указатели и счётчики, не строковые буферы
- Байт-паттерн «62ec» в листинге отсутствует (negative result)
- Grow-функция (sub_1084270) пишет только в глобалы массива/ёмкости, НЕ в указатель

Порча произошла через косвенную запись из неустановленного кода. Без полного минидампа или аппаратной точки останова источник не идентифицировать.

7. Воспроизведение вылета
--------------------------
Условие активации: сетевая игра с несколькими игроками; вылет при обработке события «игрок отключился», если к этому моменту глобал очереди уже повреждён.

Базовый сценарий:
- Запустить сетевую партию (2+ игрока)
- Играть до момента отключения одного из игроков (обрыв связи, выход из игры)
- Наблюдать вылет в цикле приёма сетевых сообщений

Варьирование:
- Разные карты (RMG/сценарии) — не влияет на механизм
- Воспроизводится на R33 и R35 (и, вероятно, на промежуточных версиях)

Дифф-тест:
- Повторить с <Sys.FullDump> = 1 в hota.ini — полный минидамп позволит проверить содержимое .data-секции и кучи вокруг глобала
- Аппаратная точка останова (отладчик): bp на запись по адресу runtime_base + offset_глобала (R33: +0x21575C, R35: +0x216744)

Роль 2 (рантайм-проверка):
- Установить hardware breakpoint на запись по адресу глобала
- Зафиксировать, какая инструкция и из какой функции записывает мусор/ноль
- Для R35-пути: проверить, не вызывается ли atexit-очистка преждевременно

8. Достоверность и ограничения
-------------------------------
Подтверждено:
- Механизм обоих вылетов доказан арифметикой: R33 — EAX = 0x63653236 = адрес сбоя; R35 — EAX = 0, [EAX+8] = 0x8 = адрес сбоя
- Листинги R33 и R35 верифицированы по entry point; функция побайтно идентична между версиями
- Цепочка вызовов подтверждена V2: caller-адреса h3hota.exe совпадают в обоих дампах
- Два РАЗНЫХ значения порчи одного глобала подтверждают, что это не артефакт одного дампа
- Неполная проверка на NULL доказана кодом: `jz` пропускает только одно разыменование

Ограничения:
- Минидампы сокращённые (103 и 139 КБ, без кучи): содержимое объектов .data недоступно
- Источник порчи не определён: прямые writer'ы корректны, косвенная запись из неустановленного кода
- Пользовательские комментарии отсутствуют (блок Comment содержит только автотекст репортёра)
- Для R35-пути (NULL): нельзя статически отличить «порча нулём» от «преждевременная atexit-очистка»


ВЫВОД
-----
Вылеты HD_HOTA.dll+0x5313C (R33) и +0x534BE (R35) — повреждение глобального указателя очереди сетевых сообщений. Два дампа, два значения порчи одного глобала: ASCII-текст (0x63653236) в R33 и NULL в R35. Вылет при извлечении сообщения из кольцевой очереди в обработчике «игрок отключился» (сетевая игра, начало партии). Код очереди корректен, за исключением неполной проверки на NULL (вторичный дефект: `jz` пропускает одно разыменование, но не последующее обращение [eax+8]). Источник порчи глобала — косвенная запись из неустановленного кода, определяется только рантайм-инструментами. Полезность НИЗКАЯ: точечный фикс в точке вылета невозможен, источник порчи не идентифицирован.
